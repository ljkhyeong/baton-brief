# BATON BRIEF 테스트 작성과 정리

검증 범위 선택과 실행 명령은 [검증 절차](../../../docs/development/verification.md)를 따른다.

## 테스트 위치

- 투영 판정·주간 구간·이벤트 형식 같은 순수 규칙은 `domain` 단위 테스트에 둔다. Spring·DB가 필요 없는
  규칙을 통합 테스트로 올리지 않는다. `application`은 별도 테스트 모듈이 없다.
- HTTP·DB·트랜잭션·잠금·마이그레이션은 `bootstrap`의 Testcontainers PostgreSQL 통합 테스트에 둔다.
  `BriefMvpIntegrationTest`는 `@BeforeEach`에서 테이블을 비우고 같은 컨테이너·`MockMvc`를 공유한다.
  인증 설정처럼 다른 Spring 컨텍스트가 필요할 때만 테스트 클래스를 나눈다.
- 시간 경계는 `BriefService`에 고정 `Clock`을 주입해 직전·정각·직후를 만든다. 실제 시간 경과를 기다리지 않는다.
- 구조 규칙은 `BriefArchitectureTest`에 둔다. 일반 `test`에서 제외되고 `:bootstrap:architectureTest`로 실행된다.

## 작성·정리 기준

- 삭제·통합 전 각 테스트가 잡는 실패와 대체 검증을 확인한다. 같은 조건과 실패 시점을 확인할 때만 합친다.
- 멱등·충돌·최초 증거, 리비전 판정, 롤백·재시도, 잠금 직렬화, Bearer·허용 목록과 비밀 비노출 검증은
  보존한다.
- Spring·Flyway·Jackson 자체 보장, 단순 매핑·getter, 제거된 분기만 시험하는 테스트는 추가하지 않고
  발견하면 대체 검증을 확인한 뒤 지운다.
- 기대값은 구현 계산을 복제하지 않고 고정값·저장 결과와 대조한다.
- fixture·보조 함수는 입력·상태 전이·주요 단언을 숨기지 않을 때만 추출한다. 여러 입력에 같은 규칙을
  적용할 때만 매개변수화한다.
- 테스트 이름은 동작을 설명하는 한글 백틱 이름을 유지한다. 이름을 바꾸면 검증 절차·README의 `--tests`
  예시를 함께 고친다. HANDOFF의 과거 실행 기록은 당시 이름 그대로 둔다.

## 검증

- 바꾼 테스트를 `--tests`로 선택 실행하고 실행된 테스트 수를 확인한다. 공용 fixture·보조 함수를 바꾸면
  그 사용처의 테스트도 실행한다.
- 테스트만 바꾼 작업에서 실행 JAR 생성·전체 테스트를 기본으로 추가하지 않는다. 제품 수정이 필요해지면
  사용자 요청 범위에서 해당 영역 스킬을 함께 적용한다.
