# BATON BRIEF 이벤트 흐름

## 계약을 확립한다

- `HANDOFF.md`, PRD-0001, ADR-0001과 채택한 모든 이벤트 계약 문서를 읽는다.
- 사용자가 해당 저장소를 범위에 포함한 경우에만 생산자 코드와 계약을 점검한다.
  그렇지 않으면 생산자 변경을 명시적인 선행 의존 작업으로 다룬다.
- PRD-0002를 채택한 로컬 MVP 계약으로 사용한다. 내부 HTTP, v1 세 타입과 v2 다섯 타입,
  최상위 `sourceReference`/`state`, 의미론적 지문 결과와 집계 리비전 규칙을
  따른다. 운영 인증, 브로커, 생산자 변경과 격리 해제 운영은 채택한 MVP 범위 밖으로
  유지한다.
- PRD-0007을 이벤트 식별자별 최초 수신 증거의 읽기 전용 조회 계약으로
  사용한다.
- PRD-0011을 작업공간·시즌별 이상 수신 증거 이력의 읽기 전용 조회 계약으로 사용한다.
  `APPLIED_WITH_GAP`, `STALE`, `UNSUPPORTED` 또는 최초 충돌이 있는 기록만 대상으로 삼는다.
- PRD-0016을 복합 정체성별 적용 상태 전이 증거의 읽기 전용 조회 계약으로 사용한다.
  `APPLIED`·`APPLIED_WITH_GAP`만 전이로 다루고 원본 집계 리비전 순서를 사용한다.
- PRD-0018을 BATON 생산자 호환성 선행조건으로 사용한다. 현재 BATON 조회 신호와 BRIEF
  이벤트 v1을 이름만 매핑하지 않고 권위 있는 의미, 영속 정체성·상태 생명주기, 외부
  집계 리비전, 시간 경계 재조정과 전용 outbox가 정해질 때까지 직접 연동하지 않는다.
- BATON PRD-0006에서 채택한 다섯 신호와 `CRITICAL`·`WARNING`, 영속 `signalId`, 신호별
  연속 리비전과 멱등 시간 재조정을 생산자 의미의 기준으로 사용한다. 이를 v1 enum이나
  규칙에 끼워 맞추지 않고 BRIEF 이벤트 v2의 호환성·지문·투영 의미를 먼저 채택한다.
- BATON 원본 변경과 자동 회차 생성은 신호에 영향을 주는 경로만 같은 트랜잭션 재조정에
  연결한다. 생산자 outbox 송신은 lease와 신호별 리비전 순서를 지키고 같은 event record를
  재사용한다. 이 구현 근거를 실제 프로세스 사이 종단 간 전달 완료로 확대하지 않는다.
- PRD-0019를 이벤트 v2 소비 기준으로 사용한다. `sourceSeverity`는 v2에 필수이며 최초
  수신 증거와 fingerprint에 보존한다. v1·기존 미지원 기록의 `null`은 그대로 두고 v1
  fingerprint 바이트열을 바꾸지 않는다.
- `contracts/VERSION`과 `contracts/schemas/source-event.v2.schema.json`을 언어 중립 v2
  요청 계약 팩의 기준으로 사용한다. 현재 RC 예시는 BRIEF 소비자와 BATON 실제
  Java/Jackson serializer·송신기가 함께 사용하지만, 실제 종단 간 전달 성공 근거로
  확대하지 않는다.
- PRD-0008을 현재 보존 기준으로 사용한다. `UNSUPPORTED`를 포함한 모든 최초 수신 기록과
  이벤트별 최초 충돌 한 건은 대체 계약을 채택·마이그레이션·검증하기 전까지
  `retain-all`로 보존한다. 현재 구현·검증 근거는 `HANDOFF.md`에서 확인한다.
- 전송 상세를 구현하기 전에 이벤트 봉투, 식별자 범위, 지원 버전, 집계 리비전 또는
  워터마크와 정규 지문 입력을 정의한다.

## 수신 처리 불변식을 보존한다

- 하나의 이벤트 식별자를 정확히 하나의 정규 페이로드 지문에 결합한다.
- 애플리케이션 경계에서 저장하고 지문에 사용한 순간 시각을 PostgreSQL `TIMESTAMPTZ`
  마이크로초 정밀도로 정규화한다. `occurredAt`은 엄격한 ISO-8601 JSON 문자열로만 받는다.
- 동일 이벤트 재생은 이전에 기록한 결과와 함께 성공으로 처리하며 투영 효과를 다시 만들지
  않는다. 지원하지 않는 이벤트의 동일 재생은 `DUPLICATE`로 다시 분류하지 않고
  저장된 `UNSUPPORTED` 거부 결과를 반환한다.
- 동일한 식별자에 다른 지문이 오면 충돌로 격리한다. 충돌 페이로드로 수락된
  수신 기록이나 투영을 덮어쓰지 않는다. 이벤트 식별자마다 크기를 제한하고 민감정보를
  제거한 첫 충돌 근거만 보존한다.
- 수신 기록이나 최초 충돌 증거를 삭제·압축하기 전에 생산자 재전달 또는 원자적
  체크포인트, `eventId` 재사용 방지, PRD-0007 만료 조회와 에디션 `sourceCursor` 감사
  의미를 함께 채택한다. 숫자 TTL이나 최대 건수를 임의로 만들지 않는다.
- 수신 증거 조회는 최초 기록의 `processingOutcome`을 그대로 반환한다. 동일 재전달의
  `DUPLICATE`와 다른 지문의 `CONFLICT`로 결과를 덮어쓰지 않고, 충돌은 선택적인 최초
  `conflictDetectedAt`으로만 표현한다. 두 fingerprint와 원문 payload를 응답에 노출하지
  않는다.
- 이상 이력에는 최초 충돌이 있는 `APPLIED`를 포함하고 충돌이 없는 `APPLIED`는 제외한다.
  기존 안전한 수신 증거 필드를 재사용하며 `DUPLICATE`를 저장 결과로 만들지 않는다.
- 이상 이력은 `ingestionSequence` 내림차순 배타 키셋으로 읽는다. 충돌 증거가 최초 수신
  뒤에 추가될 수 있으므로 커서를 요청 간 스냅샷으로 표현하지 않고 최신 상태는 첫
  페이지부터 다시 조회하게 한다.
- 상태 전이 이력은 같은 복합 정체성에서 실제 적용된 최초 수신 기록만
  `aggregateRevision` 내림차순으로 읽는다. `STALE`·`UNSUPPORTED`, 동일 재전달과 충돌을
  전이로 만들지 않으며 전이별 공백 탐지와 현재 투영의 누적 공백을 구분한다.
- 명시적인 이벤트 유형과 버전으로 분기한다. 지원하지 않는 버전은 일부만 적용하지
  않고 거부하거나 격리한다.
- 원본 순서에는 집계 리비전과 계약 워터마크를 사용한다. 도착 시간을 원본 사실로
  사용하지 않는다.
- BATON 변경과 아웃박스 기록은 원본 트랜잭션에 함께 두고, 커밋 이후 최소 한 번 방식으로
  발행한다.
- 이벤트, 로그, 테스트 고정값, 오류와 메트릭 레이블에서 PII, 자격 증명, 제공자 주소,
  원문 URL과 비밀 값을 제외한다.

## 변경 절차를 따른다

1. 수락, 중복, 충돌, 미지원 버전, 잘못된 형식, 재시도 가능, 최종 실패 결과를 안정적인
   기계 판독 코드로 명시한다.
2. 결정적 페이로드 정규화와 지문 알고리즘을 정의한다. 필드 순서가 바뀔 수 있는 임의
   재직렬화 결과를 해시하지 않는다.
3. 수신 기록 영속성, 처리 상태와 투영 효과에 명시적인 원자성 및 장애 복구 계약을 부여한다.
4. 재생에 충분한 근거를 남기면서 실패 상세의 크기를 제한하고 민감정보를 제거한다.
5. 생산자/소비자 호환성과 재생 문서를 같은 변경에서 갱신한다.

## 검증한다

- HTTP 형식 검증, 도메인 의미와 데이터베이스 제약을 각각의 소유 경계에서 검증하되, 같은
  위험을 여러 테스트 계층에서 반복하지 않는다. Jackson·Bean Validation 자체 동작보다
  PRD가 채택한 표현과 결과 계약을 검증한다.
- 최초 전달, 동일 이벤트 중복, 식별자 충돌, 잘못된 형식과 미지원 버전을 테스트한다.
- 수신 증거 조회가 동일 재전달, 충돌과 재구축 뒤에도 최초 저장 결과를 유지하고 없는
  식별자를 `404 ProblemDetail`로 반환하며 저장 상태를 바꾸지 않는지 검증한다.
- 이상 이력이 작업공간·시즌 범위와 선정 조건을 지키고, 충돌이 있는 `APPLIED`, 늦게
  발견된 충돌, 내림차순 배타 페이지와 빈 범위를 읽기 전용으로 처리하는지 검증한다.
- 상태 전이 이력이 적용 리비전 순서, 전이별 공백 탐지, `STALE` 제외, 배타 커서와 복합
  정체성 범위를 지키는지 검증한다.
- 수신 기록 저장 전후의 실패, 중단 뒤 재시도와 동시 중복 전달을
  테스트한다.
- 보존 경계를 바꾸면 모든 저장 결과와 최초 충돌 한 건의 유지, 삭제 뒤 식별자 재사용
  방지와 조회·재생 호환성을 검증한다.
- 도착 순서에 의존하지 않고 오래된 리비전과 순서가 뒤바뀐 리비전을 테스트한다.
- 생산자 테스트 고정값을 소비자와 대조해 검증하고 BRIEF 실패가 BATON을 롤백할 수
  없음을 확인한다.
- 계약 팩 예시는 별도 수신 시나리오를 만들지 않고 기존 v2 PostgreSQL 통합 흐름의 실제
  요청 본문으로 사용한다. Schema 검증은 예시 형식만 소유하고 멱등성·충돌·재구축 의미를
  중복 검증하지 않는다.
- 실제 생산자 직렬화와 종단 간 전달을 확인하지 않았다면 소비자 고정값이나 기존 WATCH
  outbox 패턴만으로 BATON→BRIEF 호환 완료를 주장하지 않는다.
- 저장소가 실제로 제공하는 검증 명령만 실행한다.
