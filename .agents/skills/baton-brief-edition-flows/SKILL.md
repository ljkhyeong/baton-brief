# BATON BRIEF 에디션 흐름

## 생성 정책을 확립한다

- `HANDOFF.md`, PRD-0001, ADR-0001, 영향받는 투영 규칙과 구현된 생성 테스트를 읽는다.
- PRD-0002를 채택한 MVP 계약으로 사용한다. 명시적인 내부 HTTP 명령, IANA 시간대의
  월요일 시작 주간 `[windowStart, windowEnd)`, 규칙 v1, 고정된 로컬 `sourceCursor`, 안정적인
  `severity`·`reasonCode`·`sourceReference` 정렬, 동일 요청 범위에서 가장 최근인
  `stateFingerprint` 기반 멱등성, 작업공간/시즌별 `generation`, 불변 항목과 최대
  `generation` 기준 최신 조회를 따른다.
- 스케줄링은 하나의 애플리케이션 명령을 실행하는 계기로만 유지한다. 생성 정책을
  스케줄러 어댑터에 넣지 않는다.
- PRD-0003을 작업공간·시즌별 에디션 이력 조회 기준으로 사용한다. `generation` 내림차순,
  배타적 `beforeGeneration`, 제한된 `limit`, 요약 필드와 기존 단건 조회 연결을 유지한다.
- PRD-0005를 저장된 두 불변 에디션의 비교 조회 기준으로 사용한다. 같은 작업공간·시즌
  범위만 허용하되 세대 방향, 주간, 시간대와 규칙 버전이 다르다는 이유로 거부하지 않는다.
- PRD-0009를 주간 범위 최신 조회 기준으로 사용한다. 기존 작업공간·시즌 전역 최신 의미를
  유지하고 작업공간·시즌·`weekStart`·`zoneId`가 정확히 같은 범위의 최대 `generation`
  저장 스냅샷을 반환한다. `ruleVersion`은 필터로 받지 않고 응답에 보존한다.
- PRD-0010을 에디션 리비전 근거 기준으로 사용한다. 새 항목의 `aggregateRevision`과
  `revisionGap`을 함께 고정해 응답·`stateFingerprint`·비교에 포함하고, V3 이전 항목은
  둘 다 `null`로 유지한다. 이 변경만으로 투영·에디션 규칙 v1을 올리지 않는다.
- PRD-0008을 보존·재구축 경계로 사용한다. 재구축은 기존 에디션과 항목을 바꾸지 않으며,
  수신 기록 삭제·압축은 과거 `sourceCursor`의 감사 의미를 먼저 정의해야 한다. 잠금 코드
  경로를 별도 동시성 테스트의 직접 증거로 확대하지 않고 실제 검증 범위는
  `HANDOFF.md`에서 확인한다.

## 에디션 불변식을 보존한다

- 하나의 에디션 식별자를 하나의 작업공간, 시즌, `[windowStart, windowEnd)`, 시간대,
  규칙 버전과 정규 선택 상태 지문에 결합한다. `sourceCursor` 이동만으로 새 에디션을
  만들지 않으면서 이 값을 생성 근거로 보존한다.
- 로컬 `sourceCursor`를 투영 스냅샷과 일관되게 포착한다. 향후 원본 워터마크를 채택하면
  둘을 구분하며, 어느 값도 수신 기록 도착 시간으로 대신하지 않는다.
- `sourceCursor`를 뒷받침하는 수신 기록을 대체 계약 없이 삭제하거나 다시 번호 매기지
  않는다. 숫자 TTL을 이유로 기존 에디션의 커서나 항목을 변경하지 않는다.
- 생성에 성공하면 선택한 항목과 모든 표시 필드를 고정한다. 이후 투영 변경으로
  기존 에디션을 수정하지 않는다.
- 새 항목의 집계 리비전과 리비전 공백 근거도 함께 고정한다. 저장에서는 두 값이 모두
  있거나 모두 `null`이어야 하고 리비전은 값이 있으면 양수여야 한다. 신규 저장은 두 값을
  모두 제공하되 이전 행을 `0`·`false`로 채우거나 현재 투영에서 추정하지 않는다.
- 동일한 투영 상태, 구간, 시간대와 규칙 버전에는 명시적이고 안정적인 동률 해소 기준을
  사용해 정렬 결과가 같은 내용을 생성한다.
- 같은 요청 범위의 직전 상태와 같은 즉시 재생만 기존 에디션을 반환한다. 상태가
  `A → B → A`로 되돌아오면 역사상의 `A` 에디션을 재사용하지 않고 새 세대로 기록한다.
- 변경 가능한 “최신” 개념을 에디션 내용과 분리한다.
- 전역 최신과 주간 범위 최신을 별도 포인터로 유지한다. 주간 조회도 현재 투영을 조합하지
  않고 저장된 불변 에디션과 항목만 읽는다.
- 이력은 불변 `generation`을 키셋으로 탐색한다. offset이나 전체 개수 조회를 추가하지 않고
  목록에서 고정 항목 전체를 반복 반환하지 않는다.
- 비교는 `(reasonCode, sourceReference)`를 항목 키로 사용한다. `added`와 `changed`는 대상
  스냅샷 순서, `removed`는 기준 스냅샷 순서를 유지하고 `changed`에 기준 `before`와 대상
  `after`를 함께 둔다.
- `aggregateRevision` 또는 `revisionGap`만 달라도 비교의 `changed`다. 두 근거를 상태
  지문에도 포함해 처음 리비전 근거를 포함한 생성은 새 세대를 만들고 이후 동일 근거는
  멱등하게 재사용한다. 기존 에디션의 지문이나 항목은 다시 계산하지 않는다.
- 비교 결과의 `removed`를 현재 투영의 `RESOLVED`로 해석하지 않는다. 저장된 두 스냅샷만
  읽고 에디션이나 투영을 변경하지 않는다.
- 정정은 새 에디션이나 채택한 명시적 대체 관계로 표현한다.
- 주입한 `Clock`을 사용하고 이름이 있는 IANA 시간대만 허용한다. 고정 오프셋은 MVP HTTP
  계약이 아니다. DST 전환에서도 순간 시각을 의도적으로 도출하고 저장·생성한 시각을
  PostgreSQL 마이크로초 정밀도로 정규화한다.

## 변경 절차를 따른다

1. 영속성이나 스케줄링을 구현하기 전에 구간 경계, 선정 규칙, 안정적인 정렬,
   빈 에디션 동작과 식별자를 정의한다.
2. 하나의 논리 요청이 서로 충돌하는 에디션을 만들 수 없도록 반복·동시 생성 의미를
   정의한다.
3. 고정한 항목과 생성 근거를 포함해 완료 상태를 원자적으로 저장한다. 또는 일부 에디션을
   공개하지 않고 복구 가능한 실패를 기록한다.
4. 예약 생성과 수동 생성이 같은 정책으로 같은 명령을 호출하게 한다.
5. 스냅샷 필드나 최신 선택 의미가 바뀌면 조회 및 호환성 계약을 갱신한다.

## 검증한다

- Java 시간 API 자체 계산이나 응답 DTO의 단순 매핑을 중복 검증하지 않는다. 채택한 실제
  구간 경계, 선정 순서, 불변성, 멱등성과 동시 생성 위험에 테스트를 집중한다.
- 고정 `Clock`으로 두 구간 경계의 직전, 경계 시점과 직후를 테스트한다.
- 채택한 시간대의 DST 누락·중첩 구간을 테스트하고 도출된 순간 시각을 검증한다.
- 반복·동시 생성, `A → B → A` 상태 회귀, 결정적 정렬과 커서 재개를 테스트한다.
- 이력 조회는 세대 역순, 범위 격리, 페이지 경계의 중복·누락과 저장 항목 수를 검증한다.
- 주간 범위 최신 조회는 전역 최신과 결과가 다른 데이터에서 정확한 범위의 최대 세대,
  범위 격리와 미존재 오류를 검증한다. 이력의 주간 필터 테스트로 대신하지 않는다.
- 비교 조회는 추가·제거·변경 분류, 기준·대상별 결정적 순서, 불변성과 대표 범위
  불일치·미존재 오류를 검증한다. DTO 단순 매핑을 별도 테스트로 반복하지 않는다.
- 리비전 근거 변경은 V3 이전 행의 두 `null`, 신규 행의 두 값 필수·양수 제약, 근거만
  다른 새 세대와 이후 멱등성, 비교 `changed` 및 재구축 뒤 불변성을 하나의 대표
  PostgreSQL 시나리오에서 검증한다.
- 생성 뒤 현재 투영을 변경하고 완료된 에디션이 그대로 유지됨을 입증한다.
- 재구축과 에디션 생성의 잠금 관계를 변경할 때 같은 전역 배타 잠금 경계의 직렬화와
  기존 에디션 불변성을 검증한다. 실행하지 않은 별도 동시성 시나리오는 성공으로
  보고하지 않는다.
- 이전 에디션 내용을 덮어쓰지 않고 정정 또는 대체 관계를 테스트한다.
