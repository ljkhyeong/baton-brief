# BATON BRIEF 투영 흐름

## 투영 기준을 확립한다

- `HANDOFF.md`, PRD-0001, ADR-0001, 영향받는 이벤트 계약과 구현된 투영기 테스트를 읽는다.
- PRD-0002 규칙 v1을 사용한다. `HANDOFF_BLOCKED`는 같은 이유 코드와 `HIGH` 심각도로,
  `ROUTINE_MISSED`와 `DECISION_FOLLOW_UP_OVERDUE`는 같은 이유 코드와 `MEDIUM` 심각도로
  변환한다. 오래된 리비전/공백 처리와 채택한 전체 재구축 경계에는 집계 리비전을 사용한다.
- PRD-0008을 동기 전역 재구축 경계로 사용한다. `UNSUPPORTED`를 제외한 보존 수신 기록을
  `ingestion_sequence` 순서로 재생하고 현재 투영만 원자적으로 교체한다. 현재 구현·검증
  근거와 직접 증명한 범위는 `HANDOFF.md`에서 확인한다.
- PRD-0013을 현재 관심 항목 단건 조회 기준으로 사용한다. 작업공간·시즌·이벤트 종류·원본
  참조의 복합 정체성을 그대로 사용하고 `ACTIVE`와 `RESOLVED`를 모두 현재 상태로
  반환한다. 목록·검색·과거 상태 이력으로 확대하지 않는다.
- PRD-0014를 현재 활성 관심 항목 목록 기준으로 사용한다. `ACTIVE`만 `eventType`과
  `sourceReference` 오름차순의 배타 키셋으로 반환하고, 커서를 요청 간 스냅샷이나 불변
  에디션의 심각도 우선 선정 순서로 해석하지 않는다.
- PRD-0015를 같은 목록의 상태 선택 기준으로 사용한다. 기본 `ACTIVE`를 보존하고
  `RESOLVED`를 선택할 때도 같은 포트·SQL·응답·키셋을 재사용하며 과거 상태 이력으로
  확대하지 않는다.
- BRIEF를 BATON 또는 WATCH 상태의 두 번째 권위가 아니라 설명 가능한 읽기 모델로 다룬다.

## 투영 불변식을 보존한다

- 결정적이고 설명 가능한 항목만 만든다. AI 출력을 권위 있는 선정 또는 상태 전이 입력으로
  사용하지 않는다.
- 표시 가능한 모든 항목에 안정적인 `reasonCode`, 범위가 제한된 `severity`, 불투명한
  `sourceReference`, `observedAt`과 적용한 규칙 버전을 부여한다. 조회·선정·재구축·설명
  계약이 소비하지 않는 별도 투영 시각은 저장하지 않는다.
- 규칙 v1처럼 현재 투영의 `reasonCode`가 `eventType`과 항상 같으면 독립 상태로 중복
  저장하지 않고 도메인에서 파생한다. 불변 에디션에는 생성 당시 `reasonCode`를 계속
  고정해 과거 스냅샷과 비교 키를 보존한다.
- 규칙 v1의 원본 `state`와 관심 항목 `status`가 같은 `ACTIVE`·`RESOLVED` 의미라면
  `SourceEventState`를 함께 사용하고 항등 enum 변환을 만들지 않는다. 수신 기록, 현재
  투영과 불변 에디션의 상태 열은 서로 다른 저장 사실이므로 합치지 않는다.
- 원본 계약의 집계 리비전으로 오래된 효과를 거부하고 공백을 식별한다. 로컬 수신 기록의
  `sourceCursor`는 에디션 근거이지 원본 워터마크가 아니다. 전달 순서로 최신 상태를
  추론하지 않는다.
- 활성, 해소와 대체 의미를 명시적으로 모델링한다. 재생 또는 설명에 필요한
  이력을 조용히 삭제하지 않는다.
- 서비스 간 외래 키로 원본 존재를 강제하거나 다른 서비스 데이터베이스를 읽지 않는다.
- 실시간 처리와 재구축에 같은 투영 규칙을 사용해, 보존한 수신 기록이 같은 규칙 버전에서
  동일한 현재 읽기 모델을 재현하게 한다.
- 재구축은 PostgreSQL 트랜잭션 advisory lock을 전역 배타 모드로 사용한다. 지원 이벤트
  수신은 같은 잠금의 공유 모드, 에디션 생성과 다른 재구축은 배타 모드로 직렬화하며,
  예외 시 이전 현재 투영으로 롤백하고 부분 결과를 공개하지 않는다.

## 변경 절차를 따른다

1. 각 원본 이벤트와 이유 코드의 대응 관계 및 리비전 의미를 문서화한다.
2. 정책을 순수하고 결정적인 규칙에 둔다. 수신 기록 조율과 저장 처리는 그 규칙
   밖에 둔다.
3. 관찰 가능한 선정, 설명 또는 수명주기 동작을 바꿀 수 있는 규칙 변경에 버전을 부여한다.
4. 새 이벤트를 적용하기 전에 리비전 공백, 오래된 이벤트, 알 수 없는 참조와 충돌 처리를
   정의한다.
5. 격리된 저장 공간이나 같은 트랜잭션의 원자적 전체 교체로 의도적으로 전환한다. 일부만
   재구축된 투영을 현재 상태로 공개하지 않는다.

## 검증한다

- 단순 enum 매핑이나 Kotlin 데이터 클래스 자체를 위한 테스트를 늘리지 않는다. 이유·심각도
  정책, 리비전 판정과 재구축 재현성을 가장 가까운 소유 경계에서 한 번 검증한다.
- 동일 이벤트 중복, 동시 중복, 오래된 리비전, 순서가 뒤바뀐 전달과 리비전 공백을 테스트한다.
- 허용되지 않는 전이 또는 무동작 전이를 포함한 모든 이유 코드와 수명주기 전이를 테스트한다.
- 현재 투영과 보존한 수신 기록을 사용한 전체 재구축 결과를 비교한다.
- 현재 단건 조회는 재구축 뒤 마지막 적용 리비전·공백 근거, 후속 `RESOLVED` 갱신과 대표
  범위 격리를 기존 PostgreSQL 수신 시나리오에서 검증한다. 응답 매핑만 위한 새 단위
  테스트는 추가하지 않는다.
- 현재 목록은 세 이벤트 종류의 정체성 순서, 배타 커서의 중복 없는 다음 페이지,
  재구축 뒤 결과와 후속 `RESOLVED` 상태별 이동을 같은 수신 시나리오에서 검증한다. 빈
  범위와 반쪽 커서는 대표 하나씩만 확인하고, 같은 페이지네이션을 상태별로 반복 검증하지
  않는다.
- 재구축 중 강제 실패가 이전 투영을 복원하는지, 지원 이벤트 수신과의 동시 실행이 같은
  전역 잠금에서 직렬화되는지 PostgreSQL 통합 테스트로 검증한다. 에디션 생성이나 다른
  재구축은 같은 잠금 코드 경로만으로 대상 동시성 테스트까지 성공했다고 보고하지 않는다.
  `UNSUPPORTED`는 보존되지만 재생 수와 투영 효과에서 제외되는지 확인한다.
- 시간 의존 투영 규칙을 추가할 때는 시스템 현재 시각을 직접 읽지 않고 주입한 `Clock`과
  고정 시각 테스트를 사용한다.
- 표시 가능한 모든 항목이 원본 데이터를 노출하지 않으면서 이유, 참조, 관측 시각과 규칙
  버전을 포함하는지 검증한다.
