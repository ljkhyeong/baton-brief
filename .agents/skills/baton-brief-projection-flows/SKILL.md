# BATON BRIEF 투영 흐름

## 투영 기준을 확립한다

- `HANDOFF.md`, PRD-0001, ADR-0001, 영향받는 이벤트 계약과 구현된 투영기 테스트를 읽는다.
- PRD-0002 규칙 v1을 사용한다. `HANDOFF_BLOCKED`는 같은 이유 코드와 `HIGH` 심각도로,
  `ROUTINE_MISSED`와 `DECISION_FOLLOW_UP_OVERDUE`는 같은 이유 코드와 `MEDIUM` 심각도로
  변환한다. 오래된 리비전/공백 처리와 채택한 전체 재구축 경계에는 집계 리비전을 사용한다.
- BRIEF를 BATON 또는 WATCH 상태의 두 번째 권위가 아니라 설명 가능한 읽기 모델로 다룬다.

## 투영 불변식을 보존한다

- 결정적이고 설명 가능한 항목만 만든다. AI 출력을 권위 있는 선정 또는 상태 전이 입력으로
  사용하지 않는다.
- 표시 가능한 모든 항목에 안정적인 `reasonCode`, 범위가 제한된 `severity`, 불투명한
  `sourceReference`, `observedAt`, 투영 시각과 적용한 규칙 버전을 부여한다.
- 원본 계약의 집계 리비전으로 오래된 효과를 거부하고 공백을 식별한다. 로컬 수신 기록의
  `sourceCursor`는 에디션 근거이지 원본 워터마크가 아니다. 전달 순서로 최신 상태를
  추론하지 않는다.
- 활성, 해소와 대체 의미를 명시적으로 모델링한다. 재생 또는 설명에 필요한
  이력을 조용히 삭제하지 않는다.
- 서비스 간 외래 키로 원본 존재를 강제하거나 다른 서비스 데이터베이스를 읽지 않는다.
- 실시간 처리와 재구축에 같은 투영 규칙을 사용해, 보존한 수신 기록이 같은 규칙 버전에서
  동일한 현재 읽기 모델을 재현하게 한다.

## 변경 절차를 따른다

1. 각 원본 이벤트와 이유 코드의 대응 관계 및 리비전 의미를 문서화한다.
2. 정책을 순수하고 결정적인 규칙에 둔다. 수신 기록 조율과 저장 처리는 그 규칙
   밖에 둔다.
3. 관찰 가능한 선정, 설명 또는 수명주기 동작을 바꿀 수 있는 규칙 변경에 버전을 부여한다.
4. 새 이벤트를 적용하기 전에 리비전 공백, 오래된 이벤트, 알 수 없는 참조와 충돌 처리를
   정의한다.
5. 격리된 저장 공간이나 동등한 공간에 구축한 뒤 의도적으로 전환한다. 일부만 재구축된
   투영을 현재 상태로 공개하지 않는다.

## 검증한다

- 단순 enum 매핑이나 Kotlin 데이터 클래스 자체를 위한 테스트를 늘리지 않는다. 이유·심각도
  정책, 리비전 판정과 재구축 재현성을 가장 가까운 소유 경계에서 한 번 검증한다.
- 동일 이벤트 중복, 동시 중복, 오래된 리비전, 순서가 뒤바뀐 전달과 리비전 공백을 테스트한다.
- 허용되지 않는 전이 또는 무동작 전이를 포함한 모든 이유 코드와 수명주기 전이를 테스트한다.
- 현재 투영과 보존한 수신 기록을 사용한 전체 재구축 결과를 비교한다.
- 투영 시각과 시간 의존 규칙에는 고정 `Clock`을 사용한다.
- 표시 가능한 모든 항목이 원본 데이터를 노출하지 않으면서 이유, 참조, 관측 시각과 규칙
  버전을 포함하는지 검증한다.
