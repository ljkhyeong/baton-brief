# BATON BRIEF 문서화 흐름

## 소유하는 기준 문서를 사용한다

- `README.md`에는 간결한 목적, 현재 기능, 실제 실행 가능한 경우에만 설정 방법, 문서
  색인을 기록한다.
- PRD-0001에는 제품 범위, 소유권, 개념, 불변식과 수용 기준을 기록한다.
- PRD-0002에는 채택한 로컬 MVP HTTP 경로, 이벤트 v1, 규칙 v1 투영, 재구축과 주간 불변
  에디션 계약을 기록한다.
- PRD-0003에는 에디션 이력의 요약 필드, `generation` 키셋, 페이지 상한과 빈 결과 계약을
  기록한다.
- PRD-0004에는 표준 `ProblemDetail` 요청 오류의 적용 범위, 표준 필드와 민감정보 비노출
  경계를 기록한다.
- PRD-0005에는 두 불변 에디션의 비교 키, 추가·제거·변경 의미, 기준·대상별 순서와
  읽기 전용 범위를 기록한다.
- PRD-0006에는 Spring Boot 표준 aggregate health의 로컬 노출 경계, 상세 비노출,
  배포 probe 제외와 운영 비목표를 기록한다.
- PRD-0007에는 이벤트 식별자별 최초 수신 증거, 중복·충돌 의미,
  fingerprint 비노출과 읽기 전용 범위를 기록한다.
- PRD-0008에는 모든 수신 결과와 최초 충돌 한 건의 `retain-all`, 불변 에디션
  `sourceCursor` 근거, `UNSUPPORTED`를 제외한 동기 전역 원자적 재구축, 삭제·압축
  선행조건과 숫자 TTL·SLO 미결정을 기록한다.
- PRD-0009에는 기존 작업공간·시즌 전역 최신과 정확한 주간·시간대 범위 최신을 구분하고,
  최대 `generation`, 저장된 불변 스냅샷, `ruleVersion` 비필터, 오류와 스키마·마이그레이션을
  추가하지 않는 경계를 기록한다.
- PRD-0010에는 새 에디션 항목의 `aggregateRevision`·`revisionGap` 고정, 응답·상태
  지문·비교 포함, V3 이전 `null` 호환성, 두 열 동시 값·양수 저장 제약과 규칙 v1 유지를
  기록한다.
- PRD-0011에는 작업공간·시즌별 이상 수신 증거의 선정 조건, 안전한 응답 필드,
  `ingestionSequence` 배타 키셋, 요청 시점 조회와 첫 페이지 새로고침, 빈 범위와
  스키마·인덱스·운영 조치 비목표를 기록한다.
- PRD-0012에는 전체 불변 에디션 응답의 불투명 `ETag`, 적용 대상 `GET`의
  `If-None-Match`·`304`, 최신 선택 변경 시 검증자 변경과 Spring MVC 표준 처리,
  캐시 TTL·저장소 비목표를 기록한다.
- PRD-0013에는 현재 관심 항목의 복합 정체성, `ACTIVE`·`RESOLVED` 단건 조회, 현재 투영과
  불변 에디션·과거 이력의 구분, 기존 기본 키·응답 재사용과 상태 변경·스키마 비목표를
  기록한다.
- PRD-0014에는 현재 `ACTIVE` 항목 선정, 복합 정체성 순서·배타 키셋, 요청 간 비스냅샷과
  첫 페이지 새로고침, 기존 기본 키·응답 재사용과 목록 필터·스키마 비목표를 기록한다.
- PRD-0015에는 같은 목록의 `ACTIVE` 기본값·`RESOLVED` 선택, 상태 조건을 유지하는 키셋,
  과거 이력과의 구분, 기존 포트·SQL·응답 재사용과 스키마 비목표를 기록한다.
- PRD-0016에는 실제 적용 상태 전이 선정, 집계 리비전 배타 키셋, 전이별 공백 탐지와 현재
  누적 공백의 구분, 보존 수신 기록 재사용과 과거 전체 투영·스키마 비목표를 기록한다.
- PRD-0017에는 현재 관심 항목 단건의 표현 버전·규칙 버전·마지막 적용 리비전에 결합한
  `ETag`, 표준 `If-None-Match`·`304`, 후속 리비전의 검증자 변경과 헤더 파서·본문 해시·
  캐시 저장소·목록 적용 비목표를 기록한다.
- PRD-0018에는 현재 BATON 신호와 BRIEF 이벤트 v1의 의미·정체성·리비전·전송 불일치,
  권위 있는 생명주기·시간 재조정·전용 outbox·실제 직렬화와 종단 간 검증 선행조건,
  BATON PRD-0006에서 채택한 생산 의미, BRIEF 소비자 v2와 BATON 실제 직렬화·생산자
  신호 스트림·불변 outbox·설정형 시간 재조정·원본 변경 자동 연결·HTTP 송신 구현과
  로컬 원본 API 변경·초기 정합화·실제 전달·전용 Bearer 근거와 HTTPS·스테이징의
  미완료 상태를 구분해 기록한다.
- PRD-0019에는 v1 호환 이벤트 v2 봉투, BATON 다섯 신호와 원본 심각도, nullable 수신
  증거, 표시 심각도 대응, V7 저장·재구축, RC 계약 팩과 생산자 구현 비목표를 기록한다.
- PRD-0020에는 BATON 이벤트 수신 전용 Bearer, 로컬 기본 비활성·필수 설정, 표준 Spring
  Security 처리, `401`과 비밀 비노출, 현재·직전 token 한 건의 수동 교체, loopback 밖
  HTTPS origin, 조회·운영 권한 및 실제 HTTPS 스테이징 비목표를 기록한다.
- ADR에는 채택한 장기 아키텍처, 기술, 전송, 저장, 보안 또는 운영 결정과
  그 장단점만 기록한다.
- ADR-0002를 채택한 Kotlin/JVM, Java 도구 체인, 바이트코드 대상, 실행 환경, Spring Boot/BOM,
  Gradle/Kotlin DSL, PostgreSQL, JDBC/Flyway, 모듈과 의존 방향 결정의 기준으로 사용한다.
- `HANDOFF.md`에는 활성 상태, 검증, 남은 결정과 다음 진입점만 기록한다.
- `AGENTS.md`와 프로젝트 로컬 스킬에는 제품 주장이 아니라 개발 작업 절차를
  기록한다.

## 문서 언어를 일관되게 유지한다

- 새 문서와 수정 문서의 제목, 본문, 상태와 설명은 한글을 기본으로 작성한다.
- 코드 식별자, API 경로, HTTP 표기, 파일명, 명령어와 공식 기술명은 원문을 유지한다.

## 주장을 사실대로 유지한다

- 구현을 나타내는 설명은 코드, 테스트, 빌드 파일, 설정, 경로, 마이그레이션과 실행
  산출물을 대조해 확인한다.
- 현재, 계획과 미결정 동작을 명확히 구분한다. 기술 스택 마이그레이션 뒤에는 이전 기술
  스택 리비전의 성공한 검증을 근거로 재사용하지 않는다. 저장소 근거가 달리 말하지 않는
  한 제품 동작, 영속성 스키마, 브로커/외부 어댑터, 실행 컨테이너 이미지, 배포와 운영 인증은
  구현되지 않았거나 미결정 상태로 둔다. 채택된 PRD만으로 구현 완료를 주장하지 않는다.
- PRD-0002부터 PRD-0020까지의 현재 구현 상태, 검증 명령과 성공 근거는 `HANDOFF.md`를
  기준으로 사용한다. 스킬에는 실행 시간, 작업 수, 캐시 적중과 현재 테스트 개수 같은
  휘발 통계를 복제하지 않는다.
- PRD-0008의 동시성 근거를 기록할 때 같은 잠금 코드 경로를 별도 동시 실행 테스트의
  직접 증거로 확대하지 않는다. 검증한 상호작용과 미검증 상호작용을 구분한다.
- 로컬 통합·기동 근거를 실제 네트워크, 생산자 연동, 운영 배포, 전달 완전성 또는 보존·
  격리 운영이 검증되었다는 주장으로 확대하지 않는다.
- 계약 팩의 JSON Schema·예시·ZIP 생성 성공을 BATON 실제 serializer, 버전 고정, 게시나
  종단 간 전달 성공으로 확대하지 않는다. 생산자 미검증 버전은 RC로 기록한다.
- MockMvc, 실행 JAR 생성과 패키지 JAR의 실제 로컬 HTTP 기동을 서로 구분한다. 실제 소켓
  요청을 확인한 경우에도 그 근거는 사용한 JDK·데이터베이스·마이그레이션·경로·응답과
  정리 범위까지만 기록하고 생산자 종단 간 연동이나 운영 배포로 확대하지 않는다.
- 빈 데이터베이스의 Flyway 전체 적용과 기존 데이터가 있는 이전 버전 스키마의 업그레이드
  검증을 구분한다. 실제 대표 행과 순차 SQL을 확인하지 않았다면 기존 데이터 호환성을
  성공으로 기록하지 않는다.
- 최소 상태 확인에는 Spring Boot Actuator의 표준 aggregate health와 자동 구성된 DB
  contributor만 사용한다. 커스텀 controller, DTO, `HealthIndicator`와 확인 SQL이 있는
  것처럼 기록하지 않는다. Spring Boot 4.1의 health probes 기본값은 `true`이므로 배포
  계약 전에는 표준 속성으로 비활성 상태를 유지한다.
- BATON, WATCH, RELAY, GO와 BRIEF의 소유권 경계를 보존한다.
- 이벤트 종류, 경로, 인증, 브로커, 스키마, 재시도, 제공자, 배포 또는 검증 결과를 만들어내지
  않는다.
- 최소 한 번 수신, 식별자/지문 충돌, 리비전 순서, 결정적 투영, 불변 에디션,
  주입한 `Clock`, 비밀정보, PII와 메트릭 카디널리티 제약을 요약할 때도 정확하게
  유지한다.

## 변경하고 검증한다

1. 기준 문서를 먼저 식별하고 갱신한다.
2. 영향받은 요약, 링크, 상태 표기와 인계 상태만 동기화한다.
3. 실행 동작이나 장기 결정이 바뀌면 같은 변경에서 문서도 갱신한다.
4. 현재 기준 설명이 오래되면 영향받은 프로젝트 로컬 스킬도 갱신한다.
5. `rg`로 오래된 용어와 서로 모순되는 현재·계획 주장을 검색한다.
6. 참조한 경로를 확인하고 `git diff --check`를 실행한다. 문서·스킬만 바뀌어 실행 산출물이
   달라지지 않으면 코드 테스트를 반복하지 않는다. 빌드 설정, 명령 또는 실행 기준도 함께
   바뀐 경우에만 가장 작은 관련 검증부터 실행한다.

문서를 사실로 만들기 위해 코드나 테스트를 바꿔야 하면 해당 구현을 소유하는 스킬을 사용한다.
