# PRD-0001: BATON BRIEF 제품 기준

- 상태: 채택됨
- 결정일: 2026-08-28
- 범위: 첫 독립 서비스 경계와 MVP

## 문제

BATON 생태계에는 역할 인수인계, 반복 운영, 결정과 자료 상태처럼 사용자가 주기적으로
확인해야 할 사실이 축적된다. 원본 화면을 모두 순회하는 대신, 특정 기간에 주의가 필요한
사실과 그 이유를 하나의 재현 가능한 운영 스냅샷으로 제공할 필요가 있다.

## 목표

- BATON의 업무 변경 이벤트를 멱등하게 수신한다.
- 사람이 이해할 수 있는 이유와 원본 참조를 가진 점검 항목을 만든다.
- 작업공간·시즌 및 시간 구간별 브리프를 생성한다.
- 같은 입력과 규칙 버전으로 같은 결과를 재현하고 전체 투영을 재구축할 수 있다.

## 비목표

- BATON의 운영 연속성 판단, 권한 또는 원본 도메인 상태 재구현
- WATCH 데이터베이스 직접 조회 또는 URL 상태 재판정
- RELAY의 구독, 제공자 호출, 재시도와 결과 관리
- GO의 공개 링크 생성·만료·폐기
- 자유 형식 AI 요약을 최종 판단 기준으로 사용
- 첫 MVP의 개인별 추천, 이메일 또는 메시지 발송

## 핵심 개념

### SourceEventReceipt

수신한 이벤트 식별자, 버전, 페이로드 지문, 수신·처리 상태와 실패 분류를 보존한다.
같은 식별자와 같은 페이로드의 재생은 기존 결과를 반환하고, 같은 식별자의 다른 페이로드는
충돌로 격리한다. 이벤트 식별자를 아는 단건 조회와 작업공간·시즌별 이상 수신 기록은
같은 최초 수신 기록과 이벤트별 최초 충돌 기록을 사용한다.

### AttentionItem

점검 사유와 원본 정보를 담은 항목이다. 최소한 다음 의미를 가진다.

- 작업공간과 시즌 참조
- 안정적인 `reasonCode`
- 제한된 `severity`
- 원본 종류와 원본 참조값
- 원본이 관측한 시간
- 적용한 규칙 버전
- 활성(`ACTIVE`) 또는 해소(`RESOLVED`) 상태

### BriefEdition

하나의 작업공간·시즌, 시간대와 `[windowStart, windowEnd)`에 대해 생성한 불변 스냅샷이다.
생성 당시 포함한 점검 항목의 표시 필드를 고정하며 이후 원본 변경으로 기존 브리프를
덮어쓰지 않는다. 새 브리프 항목은 적용한 집계 리비전과 리비전 공백 여부도 생성 근거로
함께 고정한다. 이 근거를 저장하지 않았던 이전 항목은 알 수 없는 값을 `null`로 유지한다.

## 불변식

1. 한 이벤트 식별자는 하나의 페이로드 지문과만 결합한다.
2. 한 브리프 식별자는 하나의 작업공간·시즌, 구간과 규칙 버전을 가리킨다.
3. 생성 완료된 브리프의 항목과 구간은 수정하지 않는다.
4. BRIEF는 원본 엔티티의 존재를 외래 키나 공유 데이터베이스로 강제하지 않는다.
5. 권한과 멤버십의 최종 판단은 BATON이 수행한다.
6. 도착 순서만으로 최신 원본 상태를 결정하지 않는다.
7. 명시적인 대체 보존 계약 전에는 멱등 판정, 최초 수신 기록 조회, 투영 재구축과
   브리프 `sourceCursor`의 근거인 수신 기록을 삭제하거나 압축하지 않는다.
8. 새 브리프 항목의 `aggregateRevision`과 `revisionGap`은 함께 고정하며, 이전 브리프의
   미기록 값을 추정하거나 `0`·`false`로 채우지 않는다.
9. 이상 수신 기록은 `APPLIED_WITH_GAP`, `STALE`, `UNSUPPORTED` 또는 최초 충돌이 있는
   기록으로 한정하고, 충돌이 있는 `APPLIED`를 포함한다. 조회 커서를 여러 요청에 걸친
   수신함 스냅샷으로 해석하지 않는다.

## 목표 사용자 흐름

1. BATON이 도메인 변경과 같은 트랜잭션에 아웃박스 레코드를 저장한다.
2. 커밋 이후 발행기가 버전이 있는 이벤트를 BRIEF에 최소 한 번 전달한다.
3. BRIEF가 수신 기록을 원자적으로 저장하고 점검 항목 투영을 갱신한다.
4. BATON 백엔드가 자신이 관리하는 작업공간·시즌·시간대로 생성 범위를 정하고 BRIEF의 명시적 HTTP
   명령으로 주간 브리프 생성을 요청한다.
5. BATON UI는 BATON 백엔드에서 권한을 확인한 뒤, 백엔드가 BRIEF 내부 조회를 중계한 최신
   또는 특정 브리프를 표시한다.

PRD-0002의 로컬 MVP는 BRIEF 내부 HTTP 엔드포인트까지만 구현한다. 위 흐름의 BATON 아웃박스,
발행기와 UI 변경은 이번 구현 범위가 아니다.

## MVP 수용 기준

- 완전히 같은 이벤트의 재생이 중복 점검 항목이나 브리프를 만들지 않는다.
- 같은 이벤트 식별자의 다른 페이로드가 정상 이벤트를 덮어쓰지 않는다.
- 순서가 뒤바뀐 이벤트와 투영 재구축을 테스트로 검증한다.
- 브리프 구간 경계와 일광 절약 시간 전환을 고정 시각 테스트로 검증한다.
- 모든 표시 항목에 안정적인 이유 코드와 원본 참조가 있다.
- 새 브리프 항목은 적용 집계 리비전과 리비전 공백 여부를 함께 고정하며, 이 근거만
  달라져도 새 세대로 기록하고 동일 근거의 반복 생성은 멱등 처리한다.
- 작업공간·시즌 범위의 과거 이상 수신 기록을 변경되지 않는 수신 순서를 커서로 사용해
  이전 기록을 탐색하고, 최신 상태는 첫 페이지부터 다시 조회할 수 있다.
- 이미 아는 이벤트 종류와 원본 참조로 점검 항목의 마지막 적용 상태와 리비전 근거를
  단건 조회할 수 있다.
- 작업공간·시즌의 점검 항목을 `ACTIVE` 또는 `RESOLVED` 상태별 복합 식별자 키셋으로
  발견하고 최신 상태는 첫 페이지부터 다시 조회할 수 있다.
- 복합 식별자의 실제 적용 상태 전이를 원본 집계 리비전 순서로 조회할 수 있다.
- BRIEF 장애가 BATON의 원본 변경을 롤백하지 않는다.
- 제공자, 자격 증명, 원문 비밀 값과 불필요한 PII를 저장하거나 로그에 남기지 않는다.

## 후속 결정 사항

- 수신 기록과 최초 충돌 기록의 보존 기간·용량, 격리 운영과 재구축 SLO
- RELAY와 GO를 연결할 후속 참조 계약

첫 MVP의 내부 HTTP 경로, 이벤트 v1 봉투와 이벤트 목록, 투영 규칙, 재구축과 주간
브리프 계약은 PRD-0002에서 채택한다.

PRD-0008은 보존 기간과 SLO를 정하지 않은 채 현재 `retain-all` 기준, 최초 충돌 한 건,
브리프 근거와 동기 전역 원자적 재구축 경계를 채택한다. 삭제·압축, 체크포인트와
구체적인 운영 목표는 그 문서의 선행조건을 충족하는 후속 결정으로 남긴다.

PRD-0010은 새 브리프 항목에 집계 리비전·리비전 공백 근거를 함께 고정하고, 이전
항목의 미기록 값은 `null`로 보존하는 호환성 계약을 채택한다.

PRD-0011은 `APPLIED_WITH_GAP`, `STALE`, `UNSUPPORTED`와 최초 충돌이 있는 과거 수신
증거를 작업공간·시즌별로 발견하는 읽기 전용 이력 계약을 채택한다. 충돌은 최초 수신 뒤에
생길 수 있으므로 페이지 커서는 스냅샷 토큰으로 사용하지 않는다.

PRD-0013은 기존 복합 식별자로 현재 `AttentionItem` 한 건을 조회하는 읽기 전용 계약을
채택한다.

PRD-0014는 현재 `ACTIVE` 항목만 복합 식별자 배타 키셋으로 탐색하는 목록 계약을 채택한다.

PRD-0015는 같은 목록 경로의 기본 `ACTIVE` 의미를 유지하면서 현재 `RESOLVED` 항목도 같은
복합 식별자 키셋으로 탐색하는 상태 필터 계약을 채택한다.

PRD-0016은 보존 수신 기록에서 실제 적용된 원본 상태 전이를 집계 리비전 키셋으로 조회하는
계약을 채택한다. 규칙 버전별 과거 `AttentionItem` 전체 스냅샷은 후속 결정으로 남긴다.

PRD-0017은 점검 항목 단건 응답에 규칙 버전과 마지막 적용 집계 리비전에 결합한
`ETag`를 제공하고 Spring MVC의 표준 `If-None-Match` 조건부 조회를 채택한다.

PRD-0018은 BATON이 BRIEF 이벤트를 실제 생산하기 전에 신호 정의, 안정적인
식별자·상태 생명주기·외부 집계 리비전, 날짜 변경 시 재계산, transactional outbox와 실제
생산자 직렬화·종단 간 검증을 갖추도록 선행조건을 채택한다.

PRD-0019는 기존 v1을 보존하면서 BATON의 다섯 연속성 신호와 원본 심각도를 이벤트 v2로
수신·재생하는 로컬 소비 계약을 채택한다. 이는 BATON 생산자 구현이나 종단 간 연동 완료를
뜻하지 않는다.

PRD-0020은 BATON 이벤트 수신 경로에 전용 Bearer와 현재·직전 token의 수동 교체 경계를
채택한다. PRD-0021은 최소 스테이징 실행 이미지, PostgreSQL 내부 네트워크와 파일 기반
비밀 주입 경계를 채택한다. PRD-0022는 선택적인 Caddy HTTPS 앞단에서 이벤트 수신 한
경로만 외부에 허용한다.

PRD-0023은 BATON UI가 BRIEF에 직접 접근하지 않고 BATON 백엔드가 사용자 권한을 확인한
뒤 허용한 내부 조회만 중계하는 경계를 채택한다. PRD-0024는 BATON이 대상·시간대·실행
시점을 소유하고 기존 BRIEF 브리프 생성 명령을 최소 한 번 호출하는 생성 경계를 채택한다.
PRD-0025는 두 계약의 서비스 인증과 비공개 HTTPS 연결을 이벤트 수신과 다른 Bearer와
서비스 전용 Caddy로 채택한다. 현재 구현·검증과 실제 스테이징 활성화 상태는 `HANDOFF.md`를
따른다.
