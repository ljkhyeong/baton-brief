# PRD-0003: 브리프 이력 조회

- 상태: 채택됨
- 결정일: 2026-08-14
- 주간 필터 추가: 2026-09-12
- 범위: 작업공간·시즌별 브리프 이력과 주간·시간대 필터

## 목적

PRD-0002는 작업공간·시즌 전역 최신 브리프와 식별자를 이미 아는 단건 브리프 조회를
제공한다. 그러나 상태 변화마다 새 `generation`을 보존해도 과거 `editionId`를 별도로 알고
있지 않으면 이전 스냅샷을 발견할 수 없다.

BATON UI가 작업공간·시즌 범위에서 브리프 이력을 안정적으로 탐색하고 기존 단건 조회로
이어갈 수 있도록 요약 목록 API를 추가한다. 브리프 내용과 원본 권한 판정을 복제하지
않는다.

## HTTP API

다음 내부 서비스 경로를 사용한다.

| 메서드 | 경로 | 의미 |
|---|---|---|
| `GET` | `/api/v1/workspaces/{workspaceId}/seasons/{seasonId}/editions` | 브리프 요약 이력 조회 |

경로의 `workspaceId`와 `seasonId`는 UUID다. 사용자 권한은 BATON이 판정하고,
서비스 간 인증과 접근 제한은 [PRD-0025](../0025_baton-service-api-security/spec.md)를 따른다.

### 질의 매개변수

| 이름 | 필수 | 제약 | 의미 |
|---|---|---|---|
| `weekStart` | 아니요 | `uuuu-MM-dd`, 연도 `0000`~`9999`, 월요일 | 조회할 주간의 시작일 |
| `zoneId` | 아니요 | 이름 있는 IANA 시간대 ID | 브리프 생성에 사용한 시간대 |
| `beforeGeneration` | 아니요 | 양수 | 지정한 생성 번호 이전의 브리프를 조회하는 커서 |
| `limit` | 아니요 | `1..100`, 기본값 `20` | 한 응답에 포함할 최대 브리프 수 |

숫자로 변환할 수 없는 값과 범위를 벗어난 값은 `400 Bad Request`로 거부한다.

`weekStart`와 `zoneId`는 함께 지정한다. 둘 다 생략하면 작업공간·시즌의 전체 이력을,
둘 다 지정하면 저장된 주간 시작일과 시간대 ID가 정확히 일치하는 이력만 반환한다.
예: `?weekStart=2026-08-10&zoneId=Asia%2FSeoul&limit=20`.

한 값만 지정하거나 빈 값, 잘못된 날짜, 월요일이 아닌 날짜, 고정 오프셋 또는 알 수 없는
시간대를 보내면 `400 Bad Request`다. 날짜·시간대 기준은
[주간 최신 조회](../0009_weekly-latest-edition/spec.md)와 같다.

## 응답

성공 응답은 `200 OK`이며 다음 필드를 가진다.

- `editions`: `generation` 내림차순으로 정렬된 브리프 요약 배열
- `nextBeforeGeneration`: 다음 페이지가 있을 때 마지막으로 반환한 `generation`, 없으면
  `null`

각 요약은 다음 필드만 포함한다.

| 필드 | 의미 |
|---|---|
| `editionId` | 기존 단건 조회에 사용할 브리프 식별자 |
| `generation` | 같은 작업공간·시즌에서 1부터 증가하는 브리프 생성 번호 |
| `weekStart` | 브리프 주간의 월요일 지역 날짜 |
| `zoneId` | 생성에 사용한 IANA 시간대 ID |
| `generatedAt` | 브리프 생성 시각 |
| `sourceCursor` | 생성 시 확인한 해당 작업공간·시즌의 지원 수신 기록 중 마지막 순번 |
| `ruleVersion` | 선정 규칙 버전 |
| `itemCount` | 브리프에 고정된 항목 수 |

기존 브리프를 재사용하면 생성 번호도 유지한다.

고정 항목의 표시 필드와 구간 상세는 기존 `GET /api/v1/editions/{id}`에서 조회한다. 목록
응답에 전체 항목을 중복 포함하지 않는다.

## 페이지 의미

- 첫 요청에서 `beforeGeneration`을 생략하면 조회 조건에 맞는 최대 생성 번호부터 조회한다.
- 주간·시간대 필터를 적용한 뒤 `generation` 내림차순으로 페이지를 자른다.
  생성 번호는 작업공간·시즌 전체에서 증가하므로 필터 결과에서 번호가 건너뛰어도 정상이다.
- 다음 페이지는 같은 필터와 직전 응답의 `nextBeforeGeneration`을 전달한다.
  주간이나 시간대를 바꾸면 커서를 생략하고 첫 페이지부터 조회한다.
- `beforeGeneration`보다 작은 생성 번호만 조회하므로 페이지 사이에 같은 브리프가 중복되지 않는다.
- 브리프와 생성 번호는 불변이며 새 생성 번호는 기존 최대값 뒤에만 추가되므로, 진행 중 새 브리프가
  생성되어도 이미 시작한 과거 방향 탐색에서 항목이 밀리거나 누락되지 않는다.
- 다음 페이지 존재 여부는 `limit`보다 한 건 더 조회해 판단하며 전체 개수 조회를
  수행하지 않는다.
- 해당 범위에 브리프가 없으면 `editions`는 빈 배열이고 `nextBeforeGeneration`은 `null`이다.

## 호환성과 제외 범위

- 기존 PRD-0002 API와 응답을 바꾸지 않는 추가 계약이다.
- 이벤트 v1, 투영 규칙, 브리프 생성·불변성·최신 선택 의미를 바꾸지 않는다.
- 전체 개수, offset 페이지네이션과 정렬 선택지를 제공하지 않는다.
  PRD-0009의 주간 최신 조회는 전체 브리프 한 건을, 이력 조회는 요약 목록을 반환한다.
- 브리프 항목 검색, 삭제, 보존 기간과 격리 운영 정책은 포함하지 않는다.
- BATON 멤버십, 인증·인가, 외부 시스템 연동과 운영 배포는 포함하지 않는다.

## 수용 기준

- 결과가 작업공간·시즌 범위를 벗어나지 않고 `generation` 내림차순으로 반환된다.
- `limit`을 넘지 않으며 `nextBeforeGeneration`을 사용한 다음 페이지에 중복이나 누락이
  없다.
- 각 요약의 `itemCount`가 저장된 불변 항목 수와 일치하고 `editionId`로 기존 단건 조회가
  가능하다.
- 빈 범위는 `200 OK`와 빈 배열을 반환한다.
- 잘못된 UUID, 양수가 아닌 `beforeGeneration`, `1..100` 밖의 `limit`은 `400 Bad Request`다.
- 주간·시간대를 지정하면 다른 작업공간·시즌·주간·시간대의 브리프가 섞이지 않는다.
  시차가 같은 다른 시간대 ID도 구분한다.
- 페이지 사이에 새 브리프가 생성되어도 기존 커서로 과거 이력을 이어서 조회할 수 있다.
- 주간 필터의 한 값 누락과 잘못된 날짜·시간대는 `400 Bad Request`다.
