# PRD-0012: 브리프 조건부 조회

- 상태: 채택됨
- 결정일: 2026-08-21
- 확장일: 2026-09-12 — 비교 결과의 조건부 조회 추가
- 범위: 브리프 본문·비교 결과의 `ETag`와 `If-None-Match` 조건부 조회

## 목적

BATON UI는 작업공간·시즌 전역 최신이나 선택한 주간의 최신 브리프를 반복해서 조회할 수
있다. 브리프는 생성 뒤 바뀌지 않지만 기존 API는 같은 저장 스냅샷의 전체 본문을 매번
반환한다.

ETag로 호출자가 이미 받은 브리프나 비교 결과인지 확인하고, 같으면 본문을 다시 전송하지 않는다.
브리프 저장·선정 규칙과 응답 본문은 유지한다.

## 적용 경로

다음 내부 서비스 응답에 강한 `ETag`를 포함한다. 인증과 접근 제한은
[PRD-0025](../0025_baton-service-api-security/spec.md)를 따른다.

| 메서드 | 경로 | 의미 |
|---|---|---|
| `POST` | `/api/v1/workspaces/{workspaceId}/seasons/{seasonId}/editions` | 생성하거나 재사용한 브리프의 ETag 제공 |
| `GET` | `/api/v1/workspaces/{workspaceId}/seasons/{seasonId}/editions/latest` | 현재 전역 최신으로 선택된 브리프의 조건부 조회 |
| `GET` | `/api/v1/workspaces/{workspaceId}/seasons/{seasonId}/editions/weekly/latest` | 현재 주간 범위 최신으로 선택된 브리프의 조건부 조회 |
| `GET` | `/api/v1/editions/{editionId}` | 특정 브리프의 조건부 조회 |
| `GET` | `/api/v1/editions/{targetEditionId}/changes?fromEditionId={baseEditionId}` | 두 브리프 비교 결과의 조건부 조회 |

브리프 생성의 기존 `201 Created`·`200 OK`와 `Location`, 조회의 기존 `200 OK`·`404 Not
Found` 의미는 유지한다.

## ETag 기준

- 브리프 응답 형식 버전과 저장된 `editionId`를 조합해 강한 `ETag`를 만든다.
  PRD-0029의 `section` 추가에 따라 응답 형식 버전을 올리며 HTTP 경로는 `/api/v1`을 유지한다.
- 같은 브리프를 반환하는 생성·전역 최신·주간 최신·단건 응답은 같은 `ETag`를 사용한다.
- 호출자는 `ETag` 내부 형식을 해석하지 않고 응답 값을 그대로 `If-None-Match`에 전달한다.
- 브리프 본문 형식이 바뀌면 같은 `editionId`라도 ETag가 달라지도록 응답 형식 버전을 올린다.
- 현재 투영 변경이나 재구축은 저장된 브리프를 바꾸지 않으므로 특정 브리프의 ETag도
  바꾸지 않는다.
- 비교 결과는 별도 응답 버전과 기준·대상 브리프 ID를 순서대로 조합한 ETag를 사용한다.
  기준·대상 중 하나가 달라지거나 비교 방향을 바꾸면 ETag도 달라진다.
- 비교 결과의 필드나 비교 규칙을 바꾸면 비교 응답 버전도 올린다.
  브리프 본문용 ETag를 비교 결과에 재사용하지 않는다.

전역 최신과 주간 최신의 `ETag`는 경로 자체가 아니라 요청 시점에 선택된 브리프를
나타낸다. 더 최근에 생성한 브리프가 조회 결과로 선택되면 ETag가 달라진다. 다른 주간의
새 브리프처럼 조회 결과를 바꾸지 않는 생성은 기존 주간 최신 ETag를 바꾸지 않는다.

## 조건부 응답

- 적용 대상 `GET`에 브리프 또는 비교 결과의 `ETag`와 일치하는 `If-None-Match`가 오면
  `304 Not Modified`와 빈 본문을 반환한다.
- `If-None-Match`가 없거나 ETag와 일치하지 않으면 기존처럼 `200 OK`, 해당 응답 본문과
  현재 `ETag`를 반환한다.
- 조회 범위나 식별자에 브리프가 없으면 조건부 헤더 유무와 관계없이 기존
  `404 ProblemDetail` 계약을 따른다.
- 비교 범위가 다르면 기존 `400`을 반환한다. 인증 실패도 조건부 헤더로 건너뛰지 않는다.

Spring MVC가 `ResponseEntity`의 `ETag`를 사용해 표준 조건부 요청을 처리하게 한다. 별도
헤더 파서, `304` 분기, 본문 해시 계산, 캐시 저장소와 필터를 만들지 않는다.
조건부 비교 요청도 두 브리프의 조회·범위 확인·비교 계산을 수행한다.

## 영속성과 호환성

- 기존 `BriefEdition`과 `editionId`만 사용하며 새 테이블, 열, 인덱스와 Flyway
  마이그레이션을 추가하지 않는다.
- 기존 JSON 본문 필드와 브리프 생성·선정·멱등성·불변성 규칙을 바꾸지 않는다.
- 이력 요약, 이벤트 수신 기록과 현재 투영 응답에는 이 계약을 확대하지
  않는다.
- 캐시 보관 시간, 공유 캐시 공개 가능성, 운영 인증·인가와 외부 공개 정책은 결정하지
  않는다.

## 수용 기준

- 생성 응답과 같은 브리프의 단건 조회가 같은 불투명 `ETag`를 제공한다.
- 특정 브리프는 현재 투영 변경과 재구축 뒤에도 기존 `If-None-Match`에
  `304 Not Modified`를 반환한다.
- 전역 최신 조회 결과가 새 브리프로 바뀌면 이전 최신의 `ETag`를 보낸 요청이 `200 OK`와 새
  브리프를 반환한다.
- 주간 범위 최신이 같은 브리프를 계속 가리키면 일치하는 `If-None-Match` 요청이
  `304 Not Modified`를 반환한다.
- 기존 생성 상태, `Location`, 전체 브리프 본문과 미존재 `404` 의미가 유지된다.
- 같은 기준·대상의 비교는 일치하는 ETag에 `304`를 반환하며, 현재 투영 변경·재구축 뒤에도 유지된다.
- 기준·대상 중 하나만 바꾸거나 비교 방향을 뒤집으면 기존 ETag에 새 비교 결과의 `200`을 반환한다.
- 비교 조건부 요청도 인증 실패 `401`, 범위 불일치 `400`, 기준·대상 미존재 `404`를 유지한다.

## 제외 범위

- `Cache-Control` TTL, `Expires`, 브라우저·CDN·공유 캐시 운영 정책
- 응답 본문 전체의 별도 SHA-256 계산과 캐시 검증자 저장
- 브리프 이력이나 이벤트 수신 기록의 조건부 조회
- 캐시 무효화 작업, 백그라운드 갱신과 외부 캐시 제품
- 인증·인가, 외부 공개 API와 운영 배포
