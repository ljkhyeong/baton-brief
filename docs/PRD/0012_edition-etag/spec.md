# PRD-0012: 불변 에디션 조건부 조회

- 상태: 채택됨
- 결정일: 2026-08-21
- 구현 상태: 로컬 구현 및 검증 완료
- 범위: 전체 불변 에디션 응답의 `ETag`와 `If-None-Match` 조건부 조회

## 목적

BATON UI는 작업공간·시즌 전역 최신이나 선택한 주간의 최신 에디션을 반복해서 조회할 수
있다. 에디션은 생성 뒤 바뀌지 않지만 기존 API는 같은 저장 스냅샷의 전체 본문을 매번
반환한다.

불변 에디션 식별자를 HTTP 캐시 검증자로 사용해, 호출자가 이미 가진 에디션과 선택 결과가
같으면 본문을 다시 전송하지 않게 한다. 에디션 저장·선정 의미와 기존 응답 본문은 바꾸지
않는다.

## 적용 경로

다음 인증 없는 내부 로컬 MVP 응답에 강한 `ETag`를 포함한다.

| 메서드 | 경로 | 의미 |
|---|---|---|
| `POST` | `/api/v1/workspaces/{workspaceId}/seasons/{seasonId}/editions` | 생성하거나 멱등 재사용한 에디션의 검증자 제공 |
| `GET` | `/api/v1/workspaces/{workspaceId}/seasons/{seasonId}/editions/latest` | 현재 전역 최신으로 선택된 에디션의 조건부 조회 |
| `GET` | `/api/v1/workspaces/{workspaceId}/seasons/{seasonId}/editions/weekly/latest` | 현재 주간 범위 최신으로 선택된 에디션의 조건부 조회 |
| `GET` | `/api/v1/editions/{editionId}` | 특정 불변 에디션의 조건부 조회 |

에디션 생성의 기존 `201 Created`·`200 OK`와 `Location`, 조회의 기존 `200 OK`·`404 Not
Found` 의미는 유지한다.

## 검증자 의미

- `ETag`는 API v1의 전체 에디션 표현과 저장된 `editionId`에 결합한 강한 검증자다.
- 같은 에디션을 반환하는 생성·전역 최신·주간 최신·단건 응답은 같은 `ETag`를 사용한다.
- 호출자는 `ETag` 내부 형식을 해석하지 않고 응답 값을 그대로 `If-None-Match`에 전달한다.
- 에디션 본문 표현 계약이 바뀌면 같은 `editionId`라도 이전 표현과 같은 검증자를 재사용하지
  않도록 표현 버전을 함께 변경한다.
- 현재 투영 변경이나 재구축은 저장된 에디션을 바꾸지 않으므로 특정 에디션의 검증자도
  바꾸지 않는다.

전역 최신과 주간 최신의 `ETag`는 경로 자체가 아니라 요청 시점에 선택된 에디션을
나타낸다. 더 큰 세대가 해당 조회의 새 최신으로 선택되면 검증자가 달라진다. 다른 주간의
새 에디션처럼 조회 결과를 바꾸지 않는 생성은 기존 주간 최신 검증자를 바꾸지 않는다.

## 조건부 응답

- 적용 대상 `GET`에 현재 선택된 에디션의 `ETag`와 일치하는 `If-None-Match`가 오면
  `304 Not Modified`와 빈 본문을 반환한다.
- 검증자가 없거나 현재 선택된 에디션과 다르면 기존처럼 `200 OK`, 전체 에디션 본문과
  현재 `ETag`를 반환한다.
- 조회 범위나 식별자에 에디션이 없으면 조건부 헤더 유무와 관계없이 기존
  `404 ProblemDetail` 계약을 따른다.

Spring MVC가 `ResponseEntity`의 `ETag`를 사용해 표준 조건부 요청을 처리하게 한다. 별도
헤더 파서, `304` 분기, 본문 해시 계산, 캐시 저장소와 필터를 만들지 않는다.

## 영속성과 호환성

- 기존 `BriefEdition`과 `editionId`만 사용하며 새 테이블, 열, 인덱스와 Flyway
  마이그레이션을 추가하지 않는다.
- 기존 JSON 본문 필드와 에디션 생성·선정·멱등성·불변성 규칙을 바꾸지 않는다.
- 이력 요약, 에디션 비교, 이벤트 수신 증거와 현재 투영 응답에는 이 계약을 확대하지
  않는다.
- 캐시 보관 시간, 공유 캐시 공개 가능성, 운영 인증·인가와 외부 공개 정책은 결정하지
  않는다.

## 수용 기준

- 생성 응답과 같은 에디션의 단건 조회가 같은 불투명 `ETag`를 제공한다.
- 특정 에디션은 현재 투영 변경과 재구축 뒤에도 기존 `If-None-Match`에
  `304 Not Modified`를 반환한다.
- 전역 최신이 새 세대로 이동하면 이전 최신의 `ETag`를 보낸 요청이 `200 OK`와 새
  에디션을 반환한다.
- 주간 범위 최신이 같은 에디션을 계속 가리키면 일치하는 `If-None-Match` 요청이
  `304 Not Modified`를 반환한다.
- 기존 생성 상태, `Location`, 전체 에디션 본문과 미존재 `404` 의미가 유지된다.

## 명시적 비목표

- `Cache-Control` TTL, `Expires`, 브라우저·CDN·공유 캐시 운영 정책
- 응답 본문 전체의 별도 SHA-256 계산과 캐시 검증자 저장
- 에디션 이력·비교나 이벤트 수신 증거의 조건부 조회
- 캐시 무효화 작업, 백그라운드 갱신과 외부 캐시 제품
- 인증·인가, 외부 공개 API와 운영 배포

## 현재 구현과 검증

생성·전역 최신·주간 최신·단건 에디션 응답을 Spring `ResponseEntity`로 반환하고 API v1
표현과 `editionId`로 만든 `ETag`를 설정했다. Spring MVC의 표준 조건부 요청 처리를
사용하므로 직접 `If-None-Match`를 파싱하거나 `304` 응답을 조립하지 않는다.

기존 `edition is idempotent immutable generated and reproducible after rebuild` PostgreSQL
통합 시나리오를 확장해 다음을 확인했다.

- 생성 응답의 `ETag`로 재구축 뒤 불변 단건 에디션을 조건부 조회하면 `304`다.
- 전역 최신 세대가 `4`에서 `5`로 이동한 뒤 이전 검증자를 보내면 `200`과 세대 `5`를
  반환한다.
- 주간 최신 응답의 검증자를 같은 범위에 다시 보내면 `304`다.

대상 PostgreSQL 통합 테스트와 `./gradlew --no-daemon clean test :bootstrap:bootJar`가
성공해 저장소 전체 테스트와 실행 JAR 생성을 확인했다.
