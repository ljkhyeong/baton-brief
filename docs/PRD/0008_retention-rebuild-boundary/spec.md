# PRD-0008: 수신 증거 보존과 투영 재구축 운영 경계

- 상태: 채택됨
- 결정일: 2026-08-19
- 구현 상태: 로컬 구현 및 검증 완료
- 범위: 로컬 MVP의 수신 증거 보존 기준과 동기 전역 투영 재구축의 실패·동시성 경계

## 목적

PRD-0002의 멱등 수신과 투영 재구축, PRD-0007의 최초 수신 증거 조회, 불변 에디션의
`sourceCursor`가 같은 수신 기록을 근거로 사용한다. 이 근거를 언제까지 보존하는지와
재구축 중 수신·에디션 생성·실패를 어떻게 다루는지 명시하지 않으면 각 기능의 계약을
서로 독립적으로 유지할 수 없다.

첫 로컬 MVP에서는 삭제나 압축을 서두르지 않고 모든 수신 기록과 제한된 최초 충돌 증거를
보존한다. 현재 투영은 보존한 기록으로 동기 전역 재구축하며, 성공한 결과만 원자적으로
공개한다. 보존 기간, 처리량 목표와 운영 복구 목표의 숫자는 근거가 생기기 전까지
미결정으로 둔다.

## 보존 기준

### 수신 기록 전체 보존

- `source_event_receipt`에 저장된 `APPLIED`, `APPLIED_WITH_GAP`, `STALE`, `UNSUPPORTED`
  결과를 모두 보존한다.
- 같은 이벤트의 `DUPLICATE`와 `CONFLICT` 재전달은 최초 수신 기록의
  `processingOutcome`을 덮어쓰거나 별도 수신 기록을 만들지 않는다.
- 자동 만료, TTL, 최대 건수, 결과별 삭제, 압축과 보관 계층 이동을 구현하지 않는다.
- 대체 보존 계약을 채택하고 기존 데이터에 적용한 뒤 검증하기 전까지 이 기준을
  `retain-all`로 유지한다.

수신 기록은 다음 네 계약을 함께 지탱한다.

1. 같은 `eventId`의 동일 지문과 다른 지문을 구분하는 멱등·충돌 판정
2. PRD-0007의 이벤트별 최초 수신 증거 조회
3. 같은 규칙 버전으로 현재 `AttentionItem`을 재현하는 투영 재구축
4. 불변 에디션에 기록한 로컬 `sourceCursor`의 생성 근거

### 최초 충돌 한 건

- `source_event_conflict`는 이벤트별 최초 충돌 지문과 탐지 시각 한 건만 보존한다.
- 후속 충돌의 횟수나 시도 이력을 늘려 저장하지 않고 최초 증거를 덮어쓰지 않는다.
- 충돌 지문은 내부 판정 근거로만 사용하며 PRD-0007 조회, 오류, 로그와 메트릭에
  노출하지 않는다.
- 최초 수신 기록을 보존하는 동안 그 기록에 속한 최초 충돌 증거도 함께 보존한다.

## 불변 에디션과 `sourceCursor`

- 투영 재구축은 기존 `brief_edition`과 `brief_edition_item`을 생성·수정·삭제하지 않는다.
- `sourceCursor`는 에디션 생성 트랜잭션이 본 로컬 `ingestion_sequence` 경계다. 생산자
  누락이 없음을 뜻하는 워터마크나 수신 시각이 아니다.
- 수신 기록을 삭제하거나 다시 번호 매기면 과거 `sourceCursor`를 뒷받침하는 로컬 증거가
  사라질 수 있다. 따라서 삭제·압축 계약은 에디션 감사 의미를 먼저 정의해야 한다.
- 정정은 기존 에디션 변경이 아니라 새 에디션이나 별도로 채택한 대체 관계로 표현한다.

## 동기 전역 투영 재구축

`POST /api/v1/projections/rebuild`는 작업 ID, 진행률, 취소 또는 재개 토큰을 만들지 않는
동기 전역 명령이다.

1. 재구축 트랜잭션은 투영 전역 PostgreSQL 트랜잭션 advisory lock을 배타적으로 획득한다.
2. 투영 효과가 있는 지원 이벤트 수신은 같은 전역 잠금을 공유 모드로 사용한다. 에디션
   생성과 다른 재구축은 배타 모드를 사용해 같은 경계에서 직렬화한다.
3. `UNSUPPORTED` 수신 기록은 보존하되 투영 효과가 없으므로 재생 입력에서 제외한다.
   미지원 기록 저장은 이벤트 식별자 잠금과 수신 원자성만 지키며 전역 투영 잠금에
   참여하지 않아도 된다.
4. 나머지 수신 기록을 `ingestion_sequence` 오름차순으로 읽고 실시간 처리와 같은
   규칙 버전, 집계 리비전, 오래된 이벤트와 공백 판정을 적용한다.
5. 현재 `attention_item` 전체 교체는 재생과 같은 트랜잭션에서 수행한다. 예외가 발생하면
   트랜잭션을 롤백해 이전 현재 투영을 그대로 유지하고 부분 결과를 공개하지 않는다.
6. 성공 응답의 `receiptCount`는 재생한 비미지원 수신 기록 수, `itemCount`는 교체 뒤의
   현재 관심 항목 수다.

동기 명령이라는 사실은 운영 SLO, HTTP 제한 시간이나 허용 가능한 잠금 대기 시간을
결정한 것이 아니다.

## 삭제·압축 선행조건

수신 기록, 최초 충돌 증거 또는 불변 에디션의 삭제·압축·외부 보관을 구현하려면 다음을
먼저 하나의 호환 가능한 계약으로 채택하고 마이그레이션과 복구 테스트로 검증해야 한다.

- 보존 대상별 기간·용량 근거, 삭제 계기와 법적·개인정보 요구 사항
- 삭제한 기록 없이도 재구축할 수 있는 생산자 재전달 보장 또는 버전이 있는 원자적
  체크포인트. 체크포인트에는 규칙 버전, 집계 리비전과 공백, 로컬 커서 의미가 포함되어야
  한다.
- 삭제한 `eventId`가 새 이벤트로 다시 수락되지 않게 하는 tombstone 또는 이벤트 식별자
  재사용 금지 계약
- PRD-0007 조회 대상이 만료됐을 때의 상태와 HTTP 응답 의미
- 과거 에디션 `sourceCursor`를 감사할 때 삭제된 수신 구간을 해석하는 방법
- 최초 수신 기록과 그 충돌 증거를 원자적으로 처리하는 참조 무결성 및 복구 순서
- 운영 인증·인가, 삭제 감사, 백업·복원과 실패 시 롤백 절차
- 현재 투영 잠금, 트랜잭션, Flyway 마이그레이션과 구·신 재생 경로의 호환성

일부 선행조건만으로 삭제를 시작하거나, 조회에서 보이지 않게 하는 것을 안전한 삭제로
간주하지 않는다.

## 미결정 운영 항목

다음 항목은 이 PRD에서 숫자나 구현 방식을 정하지 않는다.

- 결과별 보존 기간, TTL, 최대 건수와 저장 용량
- 재구축 완료 SLO, 최대 잠금 대기와 HTTP 제한 시간
- 진행률, 취소, 재개, 실패 재시도와 운영자 알림
- 수동·예약 실행, 전역·범위 재구축 선택
- 체크포인트 형식, 버전과 보관 위치
- BATON 생산자의 과거 이벤트 재전달 범위와 완전성 보장
- 운영 호출 인증·인가와 감사 주체
- 메트릭·경보 기준, RPO와 RTO

## 비목표

- 수신 기록, 충돌 증거 또는 에디션 삭제·압축·외부 보관 구현
- 백그라운드 작업, 스케줄러, 작업 큐, 진행률과 취소 API
- `UNSUPPORTED` 또는 충돌 페이로드의 투영 재생
- 재구축으로 기존 에디션을 정정하거나 `sourceCursor`를 다시 쓰는 동작
- 로컬 수신 순서로 생산자 전달 완전성을 추론하는 동작
- 운영 배포, 인증·인가와 숫자 SLO 채택

## 수용 기준

- 모든 저장된 수신 결과와 이벤트별 최초 충돌 한 건이 명시적 대체 계약 전까지
  삭제·압축 없이 보존된다.
- 동일 재전달과 후속 충돌이 최초 수신 결과나 최초 충돌 증거를 덮어쓰지 않는다.
- 동기 전역 재구축이 `UNSUPPORTED`를 제외한 기록을 `ingestion_sequence` 순서와 같은
  투영 규칙으로 재생한다.
- 재구축 전후에 수신 기록, 최초 충돌 증거와 기존 불변 에디션이 바뀌지 않는다.
- 재구축 중 강제 실패가 이전 현재 투영을 복원하고 부분 결과를 남기지 않는다.
- 재구축과 지원 이벤트 수신의 동시 실행이 전역 잠금 경계에서 직렬화되어 일관된
  결과만 공개한다.
- 임의의 TTL, 용량 상한, 제한 시간이나 SLO를 코드·설정·문서에 만들지 않는다.

## 현재 구현과 검증

현재 영속성 구현은 트랜잭션 advisory lock, 수신 순서 기반 비미지원 기록 재생과 같은
트랜잭션의 현재 투영 교체를 사용한다. 수신 기록은 `JdbcClient`/JDBC 표준 스트림으로
순서대로 처리해 `retain-all` 입력 전체를 목록으로 중복 적재하지 않는다.

- 기존 `edition is idempotent immutable generated and reproducible after rebuild` PostgreSQL
  통합 시나리오를 확장해 재구축 중 데이터베이스 제약 위반을 강제로 발생시켰다. 예외 뒤
  관심 항목 수가 이전 값으로 복원되고 기존 에디션이 재사용되어 원자적 롤백과 부분 결과
  비노출을 확인했다.
- 기존 `serializes concurrent duplicate ingestion edition generation and rebuild`
  PostgreSQL 통합 시나리오를 확장해 배타 재구축이 진행되는 동안 지원 이벤트 수신의
  투영 단계가 대기하고, 재구축 종료 뒤 두 작업이 순서대로 성공함을 확인했다.
- 에디션 생성과 다른 재구축도 구현에서 같은 전역 배타 잠금 경로를 사용한다. 다만 위
  대상 테스트가 두 별도 동시 실행 시나리오까지 직접 증명한 것으로 확대하지 않는다.
- `./gradlew --no-daemon clean test :bootstrap:bootJar`가 성공했고 실행 JAR 생성을
  확인했다.
