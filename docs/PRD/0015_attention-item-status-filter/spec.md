# PRD-0015: 현재 관심 항목 상태 필터 조회

- 상태: 채택됨
- 결정일: 2026-08-22
- 범위: 기존 현재 관심 항목 키셋 목록의 `ACTIVE`·`RESOLVED` 상태 선택

## 목적

PRD-0014의 목록은 현재 `ACTIVE` 항목을 발견하지만, 해소된 정체성을 목록으로 확인하려면
모든 이벤트 종류와 원본 참조를 미리 알고 PRD-0013 단건 조회를 호출해야 한다.

기존 목록 경로와 키셋을 그대로 사용하면서 현재 상태를 선택하게 한다. 기본값은 기존과
같은 `ACTIVE`로 유지한다. `RESOLVED` 조회도 현재 투영의 마지막 상태를 보여줄 뿐 과거 상태
변경 이력이나 불변 에디션을 만들지 않는다.

## HTTP API

기존 인증 없는 내부 로컬 MVP 경로를 확장한다.

| 메서드 | 경로 | 의미 |
|---|---|---|
| `GET` | `/api/v1/workspaces/{workspaceId}/seasons/{seasonId}/attention-items` | 현재 관심 항목 상태별 키셋 조회 |

PRD-0014의 질의 매개변수에 다음 필드를 추가한다.

| 이름 | 필수 | 형식과 제약 | 의미 |
|---|---|---|---|
| `status` | 아니요 | `ACTIVE` 또는 `RESOLVED`, 기본값 `ACTIVE` | 조회할 현재 상태 |

알 수 없는 상태는 `400 Bad Request`와 PRD-0004의 표준 `ProblemDetail`로 거부한다. 별도 오류
본문이나 웹 전용 상태 enum을 만들지 않는다.

`afterEventType`, `afterSourceReference`와 `limit`의 형식·검증·기본값은 PRD-0014를 그대로
따른다.

## 선정과 키셋

- 작업공간·시즌과 요청 `status`가 모두 정확히 일치하는 현재 항목만 반환한다.
- `status`를 생략하면 `ACTIVE`를 사용해 PRD-0014와 같은 결과를 반환한다.
- `eventType`, `sourceReference` 오름차순과 배타 커서를 그대로 사용한다.
- 커서는 같은 작업공간·시즌·상태 조건에서만 다음 위치를 뜻한다. 다음 페이지 요청에서도
  같은 `status`를 유지한다.
- 다음 페이지 여부는 `limit + 1` 조회로 판단하고 전체 개수는 계산하지 않는다.

`ACTIVE`와 `RESOLVED`는 같은 현재 투영 행의 상태다. 상태별 테이블, 상태 이력, 복제된
페이지네이터나 상태별 인덱스를 만들지 않는다.

## 성공 응답과 변경 의미

응답은 PRD-0014의 `CurrentAttentionItemPageResponse`를 그대로 사용한다.

- `items`: 요청 상태와 일치하는 기존 `AttentionItemResponse` 배열
- `nextCursor`: 다음 페이지가 있으면 마지막 항목의 복합 정체성, 없으면 `null`

지원 이벤트가 같은 정체성을 `ACTIVE`에서 `RESOLVED`로 바꾸면 이후 `ACTIVE` 첫 페이지에서
빠지고 `RESOLVED` 첫 페이지에 나타난다. 반대 전이도 현재 저장 상태에 따라 같은 방식으로
반영된다. 여러 요청을 하나의 데이터베이스 스냅샷으로 묶지 않으며 최신 상태는 커서를
버리고 첫 페이지부터 다시 조회한다.

## 영속성과 호환성

- 기존 `attention_item.item_status`와 V4 복합 기본 키를 사용한다.
- 기존 SQL의 고정 `ACTIVE` 조건을 바인딩한 상태 조건으로 일반화한다.
- 애플리케이션과 영속성 포트는 상태를 명시적으로 받지만 새 조회 모델은 만들지 않는다.
- 새 테이블, 열, 인덱스와 Flyway 마이그레이션은 없다.
- 기존 호출자가 `status`를 보내지 않으면 응답 의미와 기본 페이지가 바뀌지 않는다.

## 수용 기준

- `status` 생략과 `status=ACTIVE`는 기존 활성 목록 의미를 유지한다.
- `status=RESOLVED`는 현재 해소 상태인 항목만 반환한다.
- 같은 정체성이 해소되면 후속 활성 목록에서 제외되고 해소 목록에 포함된다.
- 두 상태 모두 같은 정렬, 배타 커서, 범위 격리와 빈 페이지 계약을 사용한다.
- 알 수 없는 상태는 `400 Bad Request`다.
- 조회 전후 수신 기록, 현재 투영과 불변 에디션은 바뀌지 않는다.

## 명시적 비목표

- 과거 상태 변경 이력, 해소 시각과 상태 전이 감사 로그
- 여러 상태 동시 선택, 상태 외 필터·정렬 선택, 자유 검색과 전체 개수
- 상태 변경·재활성화 명령과 격리 운영 조치
- 새 엔드포인트, 응답 DTO, 테이블·열·인덱스와 캐시 검증자
- 인증·인가, 외부 공개 API와 운영 배포

PRD-0016은 같은 복합 정체성에 실제 적용된 상태 전이 증거를 별도 이력 경로로 제공한다.
현재 상태별 목록의 정렬·커서와 과거 전이의 집계 리비전 커서를 합치지 않는다.

[PRD-0028](../0028_attention-item-filters/spec.md)은 같은 목록의 `ACTIVE`·`RESOLVED` 모두에
선택적인 심각도·리비전 공백 필터를 추가한다. 다음 페이지에서도 상태와 필터를 함께 유지한다.
