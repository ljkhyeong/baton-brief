# PRD-0030 주간 해소 요약

- 상태: 채택됨
- 목적: BATON에서 이번 주에 해소된 항목 수와 업무·해소 시점을 현재 활성 항목과 구분해 보여준다.

## 조회 계약

`GET /api/v1/workspaces/{workspaceId}/seasons/{seasonId}/attention-items/resolutions`

필수 `weekStart`·`zoneId`는 기존 주간 에디션과 같은 월요일·IANA 시간대 검증을 사용한다.
응답은 기존 `weekStart`, `zoneId`, `windowStart`, `windowEnd`, `evaluatedAt`, `resolvedCount`에
`items`, `nextCursor`를 추가한다. 기존 요청과 요약 필드의 의미를 유지한다.
`limit`은 기본 20, 1~100이며 `afterEventType`·`afterSourceReference`는 함께 제공하거나 생략한다.
현재 목록과 같은 복합 정체성 오름차순의 배타 커서 검증을 재사용한다.
각 항목은 `reasonCode`, `sourceReference`, `resolvedAt`, `resolvedRevision`이다.
해소 시각과 리비전은 집계 근거인 활성→해소 전환에서 가져오며 이후 해소 갱신으로 바꾸지 않는다.
건수와 현재 페이지는 같은 SQL 문에서 같은 대상을 읽는다. 전체 개수는 커서 이후 개수가 아니다.
마지막 페이지의 `nextCursor`는 null이다. 빈 페이지도 전체 건수를 반환한다.
요청 간 스냅샷은 아니므로 재활성화 등으로 페이지·건수가 달라질 수 있다. 최신 결과는 첫
페이지에서 다시 확인한다. BATON 화면은 다음 페이지의 주차·시간대가 이전 페이지와 다르면
목록을 감추고 첫 페이지 재조회를 안내한다.
기간은 해당 시간대 월요일 자정부터 다음 월요일 자정 직전까지다. DST를 반영한다.
`evaluatedAt`은 주입한 `Clock`의 조회 시각이며 미래에 발생한 해소는 세지 않는다.

## 해소 집계

작업공간·시즌·이벤트 종류·원본 참조가 같은 최초 수신 증거 중 실제 적용된
`APPLIED`·`APPLIED_WITH_GAP`만 사용한다. 마지막으로 적용된 `ACTIVE`와 바로 다음
원본 리비전의 `RESOLVED` 전환이 확인되고, 현재 투영도 `RESOLVED`여야 한다.
그 전환의 원본 발생 시각이 조회 기간 안이고 조회 시각 이하여야 한 항목으로 센다.

연속된 `RESOLVED` 갱신은 해소 시점을 옮기지 않는다. 다시 활성화된 항목, 처음부터
`RESOLVED`인 항목, 활성과 해소 사이에 누락된 리비전이 있는 항목은 제외한다.
해소 뒤 적용된 기록에 새로운 리비전 공백이 있으면 누락된 재활성화를 배제할 수 없으므로
제외한다. 이후 확인된 새로운 활성→해소 전환은 그 새 전환을 기준으로 판단한다.
중복·충돌·`STALE`·`UNSUPPORTED`는 해소 증거를 추가하지 않는다.

이 수치는 확인 가능한 현재 해소 항목의 수이며 전체 업무 완료 수나 과거 특정 시점의
스냅샷이 아니다. 재활성화나 새 증거에 따라 다시 조회한 수치가 줄 수 있다.
에디션 비교의 `removed`나 현재 항목의 마지막 `observedAt`에서 추정하지 않는다.
수신 기록·현재 투영을 한 SQL 문에서 읽으며 별도 저장 상태·규칙 버전을 추가하지 않는다.

## 서비스 경계와 호환성

BATON은 사용자·작업공간·시즌 권한을 판정한 뒤 시즌 시간대와 현재 주차를 정한다.
조회는 별도 서비스 Bearer와 비공개 HTTPS 경로만 허용하며 공개 Caddy에는 추가하지 않는다.
기존 이벤트·현재 목록·상태 전이 이력·불변 에디션의 계약은 유지한다.
배포할 때는 새 조회를 제공하는 BRIEF와 서비스 Caddy 허용 경로를 먼저 반영한 뒤 BATON의
해소 요약 화면을 활성화한다. 상세 확장에는 새 경로가 필요하지 않으며 BRIEF 상세 응답을
먼저 반영한다. 구버전 BRIEF의 경로 부재를 0건으로, 목록 누락을 빈 목록으로 바꾸지 않는다.

## 검증 범위

실제 PostgreSQL 수신 시나리오로 중복·오래된 전달·공백·재활성화·반복 해소·재구축,
다른 범위 격리와 주간 경계·고정 시각, 커서 전후의 전체 건수·빈 마지막 페이지와 해소 상세를
확인한다. 재활성화 뒤 재구축한 결과도 동일한 해소 시각·리비전을 반환해야 한다. 서비스 인증과 내부 HTTPS 허용 경로를
확인하고 공개 경로가 열리지 않는지 확인한다.
