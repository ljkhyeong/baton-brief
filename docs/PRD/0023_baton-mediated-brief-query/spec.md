# PRD-0023: BATON 백엔드 경유 BRIEF 조회 계약

- 상태: 채택됨
- 결정일: 2026-08-28
- 범위: BATON 사용자가 BRIEF 현재 투영과 불변 에디션을 조회하는 애플리케이션 경계

## 목적

BATON UI는 사용자 로그인, 작업공간 멤버십과 시즌 권한을 BATON에서 이미 다룬다. BRIEF
내부 조회를 브라우저에 직접 공개하지 않고 BATON 백엔드가 권한을 확인한 요청만 BRIEF에
전달하게 한다. BRIEF는 읽기 모델을 반환하되 사용자 권한을 복제하지 않는다.

## 요청 흐름

1. BATON UI가 BATON의 사용자 API를 호출한다.
2. BATON 백엔드가 사용자 인증과 대상 작업공간·시즌 권한을 권위 있게 판정한다.
3. 권한이 확인된 범위만 별도 서비스 자격 증명과 비공개 경로로 BRIEF 내부 API에 요청한다.
4. BATON 백엔드가 사용자에게 허용한 표현만 반환한다.

사용자가 보낸 `workspaceId`, `seasonId`, `editionId`를 권한 확인 없이 그대로 BRIEF에 전달하지
않는다. 식별자만 있는 에디션 단건·비교는 BRIEF 응답의 작업공간·시즌을 확인한 뒤 사용자에게
노출한다.

## 허용한 내부 조회

BATON의 사용자 기능은 필요에 따라 다음 BRIEF 읽기 계약을 조합할 수 있다.

- PRD-0013·0015·0016·0017의 현재 관심 항목 단건·상태별 목록·전이 증거
- PRD-0027의 작업공간·시즌별 현재 활성 관심 항목 요약
- PRD-0003·0005·0009·0012의 에디션 전역 최신·주간 최신·단건·이력·비교

BRIEF 경로를 BATON의 공개 사용자 API와 일대일로 노출할 필요는 없다. BATON이 응답을 그대로
전달하면 BRIEF의 `ETag`·`304`를 보존할 수 있다. 응답을 재구성하면 BATON이 그 사용자 표현의
검증자를 별도로 소유하고 BRIEF 검증자를 그대로 재사용하지 않는다.

다음 경로는 사용자 조회 대상이 아니다.

- 이벤트 수신과 수신 증거 단건·이상 이력
- 투영 전체 재구축
- Actuator 상태 확인
- 에디션 생성 명령

운영 화면에서 수신 증거가 필요하면 사용자 조회와 분리된 운영자 권한 계약을 먼저 채택한다.

## 인증과 노출 경계

- BATON이 사용자 인증·멤버십·작업공간과 시즌 접근 권한을 소유한다.
- BRIEF는 사용자 token, 세션, 멤버십과 BATON 권한 데이터를 저장하지 않는다.
- BATON→BRIEF 호출은 PRD-0020의 이벤트 수신 Bearer와 다른 서비스 자격 증명을 사용한다.
- 현재 PRD-0022 Caddy 공개 허용 목록은 이벤트 수신 한 경로로 유지한다.
- 서비스 자격 증명의 방식, 교체, 권한 범위와 비공개 네트워크 연결은 PRD-0025를 따른다.

권한이 없거나 존재를 공개하면 안 되는 대상의 사용자 HTTP 표현은 BATON 정책이 소유한다.
BRIEF의 빈 페이지나 `404`를 사용자 권한 판정으로 사용하지 않는다.
현재 활성 항목이 없는 요약의 `0` 역시 대상 존재 여부나 사용자 권한을 뜻하지 않는다.

## 일관성과 실패 의미

- 현재 관심 항목 목록과 전이 이력의 키셋은 요청 간 스냅샷이 아니다. BATON은 최신 상태를
  다시 읽을 때 첫 페이지부터 요청한다.
- 현재 활성 항목 요약과 목록도 서로 다른 요청 시점의 값을 반환하므로 두 응답 사이의
  개수 일치를 보장하지 않는다.
- 불변 에디션 단건은 생성 뒤 바뀌지 않지만 전역·주간 최신 포인터는 새 세대가 생기면
  달라질 수 있다.
- BRIEF의 네트워크 실패나 `5xx`를 권한 없음이나 빈 데이터로 바꾸지 않는다.
- BATON이 캐시를 도입하려면 BRIEF의 `ETag` 의미와 사용자 표현 변환 여부를 기준으로 별도
  만료·재검증 계약을 먼저 정한다.

## 수용 기준

- 브라우저가 BRIEF나 Caddy의 내부 조회 경로에 직접 접근하지 않는다.
- BATON이 사용자와 대상 범위를 확인한 뒤에만 BRIEF 조회를 수행한다.
- 다른 작업공간·시즌의 결과와 운영 전용 수신 증거가 사용자 응답에 섞이지 않는다.
- BRIEF 장애와 권한 거부를 서로 다른 결과로 다룬다.
- 직접 전달한 불변 응답의 `ETag`·`304` 의미가 유지되고, 변환한 표현은 BATON이 별도
  검증자를 소유한다.
- 실제 BATON 인증 사용자→BATON 백엔드→BRIEF→사용자 응답의 허용·거부 종단 간 시나리오를
  검증하기 전에는 구현 완료로 표시하지 않는다.

## 비목표

- 이번 BRIEF 변경에서 서비스 인증, 비공개 ingress와 BATON client를 구현하는 작업
- BRIEF의 사용자 계정·세션·멤버십·CORS와 공개 API 추가
- 수신 증거·재구축·health의 사용자 노출
- 자유 검색, 여러 범위를 합친 통계, 새 캐시나 GraphQL gateway
- 현재 Caddy의 이벤트 수신 외 공개 경로 확장
