# PRD-0029: 주간 브리프의 이번 주 변경과 이전 미해소 구분

- 상태: 채택됨
- 결정일: 2026-09-05
- 범위: 브리프 선정 규칙 v2, 항목 분류와 기존 브리프 호환성

## 목적

지난주에 발생한 운영 문제가 이번 주에도 미해소라면 주간 브리프에서 계속 확인할 수 있어야
한다. 기존 주간 생성 명령과 `items` 배열을 유지하고, 각 항목의 `section`에 생성 당시의
분류를 고정한다.

## 선정과 분류

생성 트랜잭션에서 같은 작업공간·시즌의 현재 `ACTIVE` 항목 중 `observedAt < windowEnd`인
항목을 선정한다. 현재 `RESOLVED`이거나 `observedAt >= windowEnd`인 항목은 제외한다.

| `section` | 화면 의미 | 선정 조건 |
| --- | --- | --- |
| `CURRENT_WEEK` | 이번 주 변경 | `windowStart <= observedAt < windowEnd` |
| `CARRY_OVER` | 이전부터 미해소 | `observedAt < windowStart` |
| `null` | 분류 미기록 | V9 이전에 저장한 브리프 항목 |

`observedAt`은 마지막으로 적용한 원본 이벤트의 시각이다. 최초 발생 시각이나 미해소 기간을
추정하지 않는다. 이전 문제의 심각도가 이번 주에 바뀌면 `CURRENT_WEEK`에만 포함한다.
항목은 한 번만 포함하며 분류별 배열이나 집계 테이블을 복제하지 않는다.

`CURRENT_WEEK`, `CARRY_OVER` 순서로 배치하고, 각 그룹 안에서 `HIGH`, `MEDIUM`,
`reasonCode`, `sourceReference` 순서로 안정 정렬한다. 시간대와 DST의 주간 경계는 기존
`WeeklyWindow`를 그대로 사용한다. 생성 시점에 읽은 현재 투영을 사용하며 과거 주말 시점의
원본 상태를 복원하지 않는다. 늦게 도착한 해소도 다음 생성에 반영한다.

## 저장과 버전

- 새 브리프의 `ruleVersion`은 선정 규칙을 나타내는 `2`다. 현재 투영과 각 항목의
  `ruleVersion`은 기존 투영 규칙 `1`을 유지한다.
- V9는 `brief_edition_item.section`에 nullable 열과 허용 값 제약만 추가한다. 기존 항목의
  분류·리비전 근거·지문·생성 번호는 다시 계산하지 않는다. 새 항목에는 분류를 반드시 저장한다.
- `section`을 기존 항목 필드들과 함께 상태 지문에 포함한다. 동일 범위·규칙의 직전 상태만
  재사용하며 규칙 v1 브리프는 빈 브리프여도 v2 생성 결과로 재사용하지 않는다.
- 분류만 달라도 비교의 `changed`에 포함한다. 이전 `null`을 현재 투영으로 채우지 않는다.
- 전역·주간 최신 조회는 규칙으로 필터링하지 않고 기존 최대 `generation` 포인터를 따른다.
- 전체 브리프 응답의 표현이 바뀌므로 불투명 `ETag`의 표현 버전도 올린다. 기존 표현의
  검증자로 새 응답을 `304` 처리하지 않는다. Spring MVC의 표준 조건부 요청 처리는 유지한다.

## 소비자 호환성

생성·전역 최신·주간 최신·단건의 `items`, 비교의 `added`·`removed`·`changed.before`·
`changed.after`에 `section`이 추가된다. BATON은 저장된 값을 중계하고 화면에서 그룹을
구분한다. `null`인 이전 항목은 분류 미기록으로 표시하며 현재 날짜로 다시 분류하지 않는다.
알 수 없는 필드를 거부하는 소비자는 BRIEF 배포 전에 응답 계약을 갱신해야 한다.

이 변경은 BATON 이벤트 요청 Schema·v1/v2 지문·이벤트 계약 팩 버전을 바꾸지 않는다.
BATON 실제 소비자·브라우저 검증 범위는 `HANDOFF.md`에 별도로 기록한다.

## 검증 기준

- 대표 이전 데이터의 항목·리비전 근거·지문을 보존하고 분류만 `null`로 유지한다.
- 시작 직전·시작·끝 직전·끝 경계의 분류·제외와 그룹별 정렬을 확인한다.
- 이전 규칙의 빈 브리프를 재사용하지 않으며 같은 새 상태는 멱등하게 재사용한다.
- 늦은 해소와 오래된 리비전 뒤 새 생성만 달라지고 기존 브리프는 유지된다.
- 재구축·동시 생성·상태 회귀의 기존 계약을 유지하고 분류 변경은 비교에 나타난다.
