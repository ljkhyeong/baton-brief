# PRD-0033: 점검 항목 연속 활성 시작 시각

- 상태: 채택됨
- 결정일: 2026-10-12
- 범위: 현재 점검 항목과 브리프 항목에 현재 활성 구간의 시작 시각(`activeSince`)을 추가

## 목적

`observedAt`은 마지막으로 적용한 원본 이벤트의 시각이다. 심각도만 바뀐 갱신도 이 값을 옮기므로
[PRD-0029](../0029_edition-carry-over/spec.md)의 이전 미해소(`CARRY_OVER`) 항목이 언제부터 미해소인지,
이번 주 변경(`CURRENT_WEEK`) 항목이 새 문제인지 기존 문제의 갱신인지 알 수 없다.
BRIEF는 적용한 리비전 순서를 알고 있으므로 투영할 때 현재 활성 구간의 시작 시각을 함께 기록한다.
BATON은 이 값으로 미해소 기간을 표시할 수 있다.

## 판정 규칙

`activeSince`는 현재 `ACTIVE` 상태가 리비전 공백 없이 이어진 첫 활성 이벤트의 원본 `occurredAt`이다.
`APPLIED`·`APPLIED_WITH_GAP`으로 적용한 이벤트마다 다음과 같이 정한다.

| 적용한 이벤트 | 직전 현재 항목 | `activeSince` |
| --- | --- | --- |
| `RESOLVED` | 무관 | `null` |
| `ACTIVE`, 직전 리비전의 바로 다음 리비전 | `ACTIVE` | 직전 값 유지 |
| `ACTIVE`, 리비전 공백 | `ACTIVE` | 이번 이벤트의 `occurredAt` |
| `ACTIVE` | 없음 또는 `RESOLVED` | 이번 이벤트의 `occurredAt` |

- 심각도 변경처럼 활성이 이어진 갱신은 시작 시각을 옮기지 않는다.
- 공백 사이에 해소가 있었을 수 있으므로 공백 뒤 활성은 새 시작으로 본다. 확인된 연속 구간만
  나타내며, 더 이전부터 활성이었을 가능성은 누적 `revisionGap`으로 함께 판단한다.
  [PRD-0030](../0030_weekly-resolution-summary/spec.md) 주간 해소가 공백 사이를 추정하지 않는 기준과 같다.
- 늦게 도착한 리비전은 `STALE`이므로 이미 기록한 시작 시각을 고치지 않는다. 재구축도 같은 수신
  순서로 재생하므로 같은 값을 만든다.
- 원본 시각의 순서를 검사하거나 보정하지 않는다. 미해소 기간을 계산할 기준 시각은 BATON이 정한다.

## 응답

- 현재 항목 단건·목록과 이벤트 수신 응답의 `item`([PRD-0013](../0013_current-attention-item/spec.md),
  [PRD-0014](../0014_active-attention-items/spec.md))에 `activeSince`를 추가한다. `RESOLVED` 항목은 `null`이다.
- 브리프 항목과 비교의 `added`·`removed`·`changed.before`·`changed.after`
  ([PRD-0002](../0002_mvp-contract/spec.md), [PRD-0005](../0005_edition-comparison/spec.md))에 생성 당시의
  `activeSince`를 고정한다. 브리프는 활성 항목만 선정하므로 항상 값이 있다.
- 다른 시각 필드와 같은 UTC ISO-8601 문자열이며 마이크로초 정밀도다.

## 저장과 버전

- `attention_item.active_since`는 `ACTIVE`일 때만 값을 가지며 DB 제약으로 상태와 함께 검사한다.
  `brief_edition_item.active_since`는 `NOT NULL`이다.
- 생성 재사용·[최신 여부](../0031_edition-freshness/spec.md)·비교의 항목 비교에 포함한다.
  시작 시각이 바뀌는 갱신은 새 리비전이므로 `aggregateRevision`도 함께 달라진다.
- 투영·선정 규칙 버전은 바꾸지 않는다. 기존 필드의 판정은 같고, 운영 데이터가 없어 다시 계산할
  이전 값이 없다. 단일 V1 스키마에 열을 추가하므로 기존 로컬·스테이징 DB 볼륨은 다시 만든다.
- 응답 형식이 바뀌므로 현재 항목([PRD-0017](../0017_current-attention-item-etag/spec.md))과
  브리프·비교([PRD-0012](../0012_edition-etag/spec.md)) ETag의 응답 형식 버전을 올린다.
  이전 형식의 ETag로는 `304`를 반환하지 않는다.

## 소비자 호환성

- 응답 필드만 추가하며 경로·상태 코드·기존 필드는 그대로다. 알 수 없는 필드를 거부하는 소비자는
  BRIEF 배포 전에 응답 계약을 갱신해야 한다.
- BATON 화면에 표시하려면 BATON의 BRIEF 응답 DTO와 화면을 갱신해야 한다. BATON 저장소 작업은
  별도 요청으로 진행한다.
- 이벤트 요청 Schema·수신 판정·계약 팩 버전은 바꾸지 않는다.

## 제외 범위

- 시작 시각·미해소 기간 기준의 필터·정렬·집계와 기간 계산 필드
- 주간 해소 항목의 해소까지 걸린 기간
- 공백 이전 활성 구간의 추정과 원본 이벤트 재요청

## 수용 기준

- 공백 없는 활성 갱신은 시작 시각을 유지하고, 해소하면 `null`, 재활성화·공백 뒤 활성은 새 시작 시각이다.
- 재구축 뒤 같은 시작 시각을 재현하고, 같은 상태로 다시 생성하면 기존 브리프를 재사용한다.
- 생성한 브리프의 시작 시각은 이후 해소·재활성화에도 바뀌지 않으며 비교에 이전·이후 값이 나타난다.
- 이전 응답 형식의 ETag로 조건부 조회하면 `200`과 새 본문을 반환한다.
