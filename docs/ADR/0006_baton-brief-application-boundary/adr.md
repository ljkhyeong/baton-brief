# ADR-0006: BATON이 사용자 권한 확인과 브리프 생성 요청을 담당

- 상태: 채택됨
- 결정일: 2026-08-28

## 배경

BRIEF는 점검 항목과 브리프의 내부 조회 API, 멱등한 주간 브리프 생성 명령을
제공한다. 그러나 사용자 계정·작업공간 멤버십·시즌 권한은 BATON이 소유하고, 현재 공개
Caddy는 이벤트 수신 한 경로만 허용한다. BRIEF에 사용자 인증과 생성 대상을 다시 만들거나
내부 API를 브라우저에 직접 공개하면 서비스 소유권과 기존 기본 거부 경계가 깨진다.

## 결정

- BATON UI는 BRIEF를 직접 호출하지 않는다. BATON 백엔드가 사용자 인증과 작업공간·시즌
  권한을 판정한 뒤 허용된 BRIEF 내부 조회를 호출하고 결과를 사용자 API 응답으로 전달한다.
- BRIEF는 BATON 사용자·세션·멤버십 데이터를 저장하거나 판정하지 않는다. 전달받은 범위의
  읽기 모델만 반환한다.
- BATON 백엔드는 자신이 관리하는 작업공간·시즌·IANA 시간대와 실행 시점을 정하고 BRIEF의 기존
  브리프 생성 명령을 최소 한 번 호출한다. BRIEF는 결정적 선정·불변 저장·멱등성과
  `generation`을 계속 소유한다.
- 사용자 조회와 브리프 생성은 이벤트 수신 전용 Bearer를 재사용하지 않는 PRD-0025의 별도
  서비스 인증과 비공개 네트워크 경로를 사용한다.
- 현재 Caddy의 공개 허용 목록은 `POST /api/v1/events` 하나로 유지한다. 조회·생성 경로를
  같은 공개 origin에 추가하지 않는다.
- BRIEF에 사용자용 controller, 멤버십 저장소, CORS 정책, 생성 대상 registry나 자체
  scheduler를 추가하지 않는다.

## 결과

### 장점

- 사용자·작업공간 권한은 BATON에서만 확인한다.
- BRIEF는 재생 가능한 읽기 모델과 브리프 책임에 집중한다.
- BATON의 일정·시즌 정보로 생성 대상을 정하면서 BRIEF의 기존 멱등 명령을 재사용한다.
- 공개 이벤트 수신과 비공개 사용자 조회·명령의 신뢰 경계를 분리한다.

### 비용과 한계

- BATON 백엔드에 BRIEF client, 사용자 응답 구성과 생성 실행 기록이 필요하다.
- 서비스 인증과 비공개 네트워크가 준비되기 전에는 현재 스테이징에서 조회·생성을 원격
  호출할 수 없다.
- BATON에서 BRIEF로 이어지는 추가 네트워크 실패와 최종적 일관성을 사용자 경험에서
  처리해야 한다.

## 대안

- BATON UI가 BRIEF를 직접 호출: BRIEF에 사용자 인증·CORS·멤버십 판정을 중복시키고 내부
  API를 공개해야 하므로 채택하지 않았다.
- BRIEF가 자체 scheduler와 대상 registry를 소유: BATON이 관리하는 시즌·시간대·대상
  정보를 복제하므로 채택하지 않았다.
- 기존 이벤트 Bearer를 조회·생성에도 사용: 쓰기 한 경로의 비밀이 사용자 조회와 명령
  권한까지 넓어지므로 채택하지 않았다.
- Caddy에 모든 BRIEF 경로를 공개: 권한 없는 내부 API의 우회 경로가 생기므로 채택하지
  않았다.
